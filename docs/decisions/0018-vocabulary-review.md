# 0018 Phase 11 PR 1: 語録の確認シートと統計ツール

日付: 2026-09-20 / 対象: Phase 11「職種専用語録。初期職種はエンジニア・営業・事務・飲食・講師教育・接客販売。単語・用語単位。ミスごとに距離減少。距離を制限時間として扱う」。Phase 11 は 2 つの PR(**確認シートと統計ツール** → 語録の拡充とバランスの再確認)に分ける。この PR は、その 1 つ目。

## 仕様と、現状の突き合わせ

| 仕様 | 状態 |
| ---- | ---- |
| 6 つの職種の語録 | **済み**(Phase 2〜4)。職種ごと 16 語(計 96 語) |
| 単語・用語単位 | **済み**。読みの長さは 2〜9 文字で、短文ではない |
| ミスごとに距離減少 | **済み**(`roles.json` の `stage` の「ミス」。エンジンのテストで検証) |
| 距離を制限時間として扱う | **済み**(時間で距離が減り、0 でつかまる) |

**Phase 11 の仕様の中心は、すでに実装されている。** 残っているのは、**語録の内容の質と量**:

1. 語録は AI(私)の**下書き**で、人間の確認(`docs/05_checklists/vocabulary-validation.md`)が、まだ済んでいない(公開はしている)
2. 語数が少ない(1 回のプレイで 14〜16 語を使うので、毎回ほぼ同じ語が出る)。難易度・カテゴリも偏っている

## スコープ

- **含める**: 語録の確認シート(生成)、統計・点検のコマンド、点検のテスト、私の一次チェックのメモ
- **含めない**(**語録のデータは、この PR では変えない**): 語の追加・修正・難易度の変更(PR 2 と、運営者の確認の後)、役職ごとの語の出し分け、語の説明の表示(Phase 12)、苦手な語の頻度(Phase 13)、Markdown からの追加・管理画面(Phase 14)

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 確認シート | `npm run vocab:review` が、語録から `docs/vocabulary-review.md` を**生成**する(手で書き換えない)。職種ごとの表(ID・日本語・読み・ローマ字・カテゴリ・難易度・説明・関連する語・私の確認メモ)と、確認の観点(正確性・表記・難易度・適切さ)、返信のしかた。`--check` で最新かを検査する(テストでも検査) | 運営者が、語を 1 つずつ読んで、直す語を、ID で伝えられるようにする。語録を変えたら、作り直す |
| 2 | 私の確認メモ | `docs/vocabulary-review-notes.json`(語の id → メモ)。**間違いを指摘するものではなく、「会社・地域・ツールで使い方が違う」「法律上の定義とは厳密には違う」など、人に見てほしい点**を書く。9 件 | AI の確認は、最終判断にしない(`docs/06_ai/content-check-prompt.md`)。**外部の資料での裏づけは、していない**(私の知識だけの一次チェック) |
| 3 | 統計・点検 | `npm run vocab:stats`: 職種ごとの語数・難易度の分布・カテゴリ数・読みの長さ、点検の結果。**エラー**(重複した id・日本語・読み)は終了コード 1、**警告**は表示だけ | 語を足すときの、偏りの見つけやすさ |
| 4 | 警告の基準 | 難易度が決め(0006: 読みの単位数が 3 以下 = 1、4〜5 = 2、6 以上 = 3。小さい ゃゅょぁぃぅぇぉ は前と合わせて 1)と違う・語数 24 未満・難易度ごとの語数 4 未満・カテゴリ 3 未満・職種をまたぐ同じ語 | 拡充の目標 |
| 5 | 警告は「増やさない」を、テストで守る | 実際の語録の警告は、**31 件以下**(難易度のずれ 17 件以下)を、テストで検査する。PR 2 で、0 にして、警告をエラーに変える | 現在のデータは、目標を満たしていないので、いま、エラーにできない。**増やさない**ことだけ、守る |
| 6 | 追加した検査 | 対象の役職が実在する・説明が空でなく「。」で終わり 80 字以内・日本語に空白がない・読みはひらがな(と ー)だけ・ローマ字は小文字の英字と `-`・**関連する語が同じ職種の実在する語を指す** | 既存のテスト(形式・入力できるか・重複なし)に足りなかった点 |

## 私の一次チェックで分かったこと

- **難易度が決めと合わない語が 17 語**(96 語中): たとえば、さーばー(4 単位)が難易度 1、れびゅー(3 単位)が難易度 2。決め(0006)は、追加した 36 語には適用したが、最初の 60 語は、別の基準(語の概念のむずかしさなど)で付いていたとみられる。**難易度は、いまのゲームでは使っていない**ので、影響はない。Phase 12 で使うので、統一が要る
- **カテゴリの偏り**: 事務・営業は 1 種類だけ、エンジニア・講師・教育は 2 種類(飲食 4・接客販売 3)
- **難易度の偏り**: 講師・教育の難易度 3 は 2 語だけ。飲食は難易度 1 と 3 が、それぞれ 3 語
- 関連する語は、すべて、同じ職種の実在する語を指していた(新しい検査を通った)

## 運営者への質問(この PR で、決めてほしいこと)

1. **難易度の決め方を統一してよいか**: 推奨は、**読みの長さの決め(0006)に、全語を合わせる**(17 語の数字を直す)。機械的に決まるので、テストで守れ、Phase 12 で予測しやすい。別案: 語の概念のむずかしさで付ける(人の判断になり、テストで守れない)
2. 確認シートの語について、直す点・削除する語(ID で)

- **語録の内容は、まだ、人間の確認を受けていない**(この PR は、その確認を助けるもの)。確認シートの読み方・返信のしかたは、シートの冒頭にある
