# 0023 Phase 13 PR 1: 苦手な語の出やすさ

日付: 2026-09-21 / 対象: Phase 13「ランダム出題+苦手用語の頻度調整。同一ゲーム内は原則重複なし。成績に正解数・正確率・速度・難易度・連続正解・残り距離。複数ローマ字表記と入力方式設定」。

Phase 13 は 3 つの PR に分ける。**この PR(1)**: 苦手用語の頻度調整。**PR 2**: 入力方式設定(ローマ字の書き方)。**PR 3**: 成績(連続正解・難易度・速度・残り距離。記録の版 3)。

## 仕様と、現状の突き合わせ

| 仕様 | 状態 |
| ---- | ---- |
| ランダム出題・同一ゲーム内は重複なし | **済み**(`pickWords`。この PR でも変えない。テストで検査) |
| **苦手用語の頻度調整** | **この PR**。元データ(語ごとのミス数 `wordMisses`)は、Phase 4 から保存済みで、復習リスト(0020)が使っている |
| 成績の項目・入力方式設定 | PR 2・PR 3 |

## 運営者が決めたこと(計画への「推奨案で」)

- 段階は **なし / ふつう(既定)/ 多め** の 3 段階。**連続タイピングだけ**(用語確認は、完全ランダムのまま)
- 進め方: 苦手頻度(この PR)→ 入力方式 → 成績(記録の版 3)

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 元データ | **直近 20 プレイ**(役職は問わない。復習リストと同じ範囲)の `wordMisses`。数え方は、復習リストと共通の `totalWordMisses`(語録にない語・ミスの数が正の整数でないものは、数えない)。**新しく保存するものはない**。記録の版・形は、変えない | 復習リストと「苦手」の意味をそろえる。移行が要らない |
| 2 | 重み | 重み = `1 + 強さ × min(ミスの数, 4)`。ミスした語だけが、1 より大きくなる。**ふつう: 強さ 0.25(最大 2 倍)/ 多め: 0.5(最大 3 倍)/ なし: 完全にランダム**。語録の `weak_detection.enabled` が `false` の語は、重みを付けない(いまは全語 `true`) | 偏りすぎない(上限)。`weak_detection` に、初めて意味を持たせる |
| 3 | 出題 | `pickWords(…, { weights })`。重みが大きい語ほど、先に出やすい重みつきの抽出(語ごとに `random^(1/重み)` を作り、大きい順)。**重みがなければ、従来と同じ結果**(同じ乱数で、同じ語・同じ順。テストで検査)。**同一ゲーム内で、同じ語は出ない**。語が足りないときの再利用も、直前と同じ語は続けない | 従来の出題を、壊さない |
| 4 | 設定 | ダッシュボードに「苦手な語の出やすさ」(選択肢: なし(完全にランダム)/ ふつう / 多め)。ラベル・説明(`aria-describedby`)つき。`settings.js` の `weakBoost` に保存(記録のキーとは別)。壊れた値・知らない値は、既定(ふつう)に戻す。以前に保存された設定(`weakBoost` がない)は、説明の設定を保って、既定を補う。用語確認では、欄を隠す | 説明の設定(0019)と同じ仕組み |
| 5 | 範囲 | **連続タイピングだけ**。用語確認(職種の 10 語)・復習リストの用語確認は、変えない | 承認済み。復習リストが、用語確認の入り口 |
| 6 | 詳細ページ | ゲームを **0.8.0** に。更新履歴・FAQ「同じ言葉ばかり出ませんか?」を追加 | 出題の挙動が変わった |

## バランスへの影響

**苦手な語を出やすくすると、その語でミスしやすい人ほど、クリア率が下がる**(苦手な語が、増えるため)。強さは、これを、シミュレーションで見て決めた。想定は、ほぼ最悪のケース: 30 語のうち 6 語が苦手(ミス率が、ほかの語の 3 倍。平均のミス率は、いつもと同じ)で、**直近の記録で、その 6 語を、完全に把握している**。クリア率(%)。ふつうの打鍵者(2.5 打鍵/秒)。

| 役職 | なし | ふつう(採用。最大 2 倍) | 多め(採用。最大 3 倍) | (参考)最初の案: ふつう 最大 3 倍 / 多め 最大 4 倍 |
| ---- | ---- | ---- | ---- | ---- |
| 係長 | 89 | 82 | 78 | 78 / 74 |
| 部長 | 66 | 56 | 50 | 50 / 45 |
| 社長 | 50 | 40 | 33 | 33 / 30 |

- 最初の案(ふつう 最大 3 倍・多め 最大 4 倍)は、部長で -16、社長で -17 ポイントまで下がるため、**強さを半分にした**(計画の「最大でも 3〜4 倍」を、「2〜3 倍」に変えた)。苦手な語のミス率が 2 倍の想定なら、影響は、ふつうで -3〜-7、多めで -5〜-11 ポイント
- 先輩(遅い人)は 86 → 79(ふつう)/ 75(多め)。速い人は、係長〜社長でも、100% のまま。会長(速い人)は 75 → 69 / 62
- **これは、難しさの選択でもある**: 「なし」にすると、これまでどおり(0006・0022 の表)。既定を「ふつう」にしたので、苦手な語が多い人は、以前より、少し難しくなる。実際の人間の手ごたえは、未確認
- バランスのテスト(`tests/balance.test.js`)は、重みなしの出題で、階段(0006・0022)を確認する。苦手な語の出やすさは、別の難しさの調整なので、階段には含めない

## 未確認・既知事項

- 実際の人間のプレイでの手ごたえ(苦手な語が出る実感・クリア率への影響)は、未確認。シミュレーションは、苦手な語を完全に把握している、ほぼ最悪の想定

- 記録がない・壊れている・直近のプレイに `wordMisses` がない(以前の版の記録)ときは、重みがなく、完全にランダム
