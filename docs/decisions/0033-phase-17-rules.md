# 0033 Phase 17 PR 1: 役職ごとの文字数と、特殊ルール

日付: 2026-09-21 / 対象: Phase 17「各役職1ステージから開始し将来追加。役職ごとに文字数・追跡速度・特殊演出・特殊ルール(後から修正可能)。会長は全役職クリアで解放。クリア・ゲームオーバーは役職別専用演出」。

Phase 17 は 3 つの PR に分ける(運営者が決めたこと。計画への「推奨案で」)。**この PR(1)**: 役職ごとの文字数・特殊ルールの中身・バランスの再調整。**PR 2**: ルールの特殊演出(予告・文字・動き)。**PR 3**: 役職別のクリア・ゲームオーバー演出。

**0022 の決定「コンボなどのルールは足さない」は、今回の仕様(特殊ルール)で、置き換わる。** 0022 のバランスの目標(階段)は、そのまま守る。

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | ステージの構造 | `stage`(1 役職 = 1 ステージ)のまま。`stages` の配列にはしない。ルール・語の重みは `stage` の中に置く。**ステージを増やす・選ぶのは Phase 18**。そのとき、記録に `stageId` を足し、`DATA_VERSION` を 4 にして、版 1〜3 を読める移行を書く | 使わない構造を、先に作らない。ルールと重みは `stage` の中にあるので、将来の `stages` の各要素に、そのまま入る |
| 2 | 役職ごとの文字数 | `stage.word_weights`(難易度 → 出やすさの重み)。難易度は、読みの長さの決め(≤3 → 1、4〜5 → 2、≥6 → 3。0006)なので、**難易度の重み = 文字数の出やすさ**。**語は削らない**(180 語すべてが、どの役職でも出うる)。苦手な語の重み(0023)と、かけ合わせる(`word-weights.js` の `mergeWeights`)。範囲は 0.1〜10 | 語録・記録・復習リストは、そのまま |
| 3 | 語の重みの値 | 先輩 {1: 3, 2: 1.5, 3: 0.4} / 係長 {1.6, 1.2, 0.8} / 部長 {1, 1, 1} / 社長 {0.7, 1, 1.6} / 会長 {0.4, 1, 2.5}。**出る語の平均の難易度**: 1.71 → 1.89 → 2.01 → 2.16 → 2.28、**平均の文字数**(標準の表記): 7.4 → 8.0 → 8.4 → 8.9 → 9.3(役職が進むほど、長い) | 先輩は入門(短い語)、会長は長い語 |
| 4 | 特殊ルールの形 | `stage.rules` = ルールの配列(種類 + 数値)。**追ってくる人が、時間で距離を縮める速さ(`drain_per_second`)にかける倍率**だけ(加算・減算はしない)。種類は 3 つ(下)。重なった倍率は、**3 倍まで**。無効なルール(知らない種類・範囲外・数でない・同じ種類の 2 つ目)は、無視する(テストで、`roles.json` が全部有効であることを検査) | 純粋な計算(`rules.js`)。将来の管理画面(Phase 26)からも、同じ検証を使える |
| 5 | ダッシュ(`surge`) | `every` 秒ごとの周期の**終わりの `duration` 秒**、`multiplier` 倍。始まる `warn` 秒前が「予告」。**時間だけで決まる**(乱数なし。覚えられる) | 予告つき。運ではなく、知っていれば備えられる |
| 6 | ミスで加速(`shock`) | ミスした瞬間から `duration` 秒間、`multiplier` 倍。続けてミスすると、そこからまた延びる(短くはならない) | 正確さを、求める |
| 7 | 追い詰め(`closing`) | 距離が最大の `from`(割合)を切ると、少なくなるほど速くなり、距離 0 で `max` 倍(直線) | 追いつかれそうなときに、さらに厳しい |
| 8 | 役職ごとのルール | **先輩 = なし**(入門)/ **係長 = ダッシュ**(15 秒ごと・3 秒間・×1.5・予告 1 秒)/ **部長 = ミスで加速**(2 秒間・×1.5)/ **社長 = 追い詰め**(50% から・最大 ×1.3)/ **会長 = 3 つとも、弱め**(ダッシュ 20 秒ごと・3 秒間・×1.3 / ミスで加速 1.5 秒間・×1.3 / 追い詰め 40% から・最大 ×1.2) | 役職ごとに、遊び方が変わる。会長は全部入りの裏ボス |
| 9 | エンジン | `engine.js` の `tick` が、`rulesOf(stage)` があれば、時間を **0.05 秒の刻み**に分けて、その間の倍率で縮める。**ルールがなければ、従来と同じ計算**(1 回の引き算)。`applyMiss` が、ミスで加速の終わる時刻(`state.shockUntil`)を記録する。不正な秒数(負・NaN・無限)の `tick` は、何もしない。DOM・時計・乱数に触れない | 画面(0.1 秒ずつ)と、シミュレーション(長い区間)で、同じ結果になる |
| 10 | 画面(この PR) | 役職を選ぶと、**その役職の特殊ルールの説明**が、役職の選択の下に出る(ルールがなければ「特殊ルールはありません」。`aria-live="polite"`・`textContent` だけ。用語確認では、役職の選択ごと隠れる)。説明の文は、データの数値から作る(`describeRule`)。**プレイ中の予告・演出は PR 2** | 知らずに始めるのは、不公平 |
| 11 | バランス | **0006・0022 の階段を保つ**。ルールと重みで、クリア率が下がる(下の表 B)ので、**`base_gain` を探し直した**(二分法。0.05 きざみ): 先輩 3.9 → **3.3**、係長 3.8 → **4.45**、部長 3.7 → **5.35**、社長 3.6 → **5.2**、会長 1.7 → **3.6**。`drain_per_second`・初期距離・ミスの減り・目標語数・倍率は、変えない | 追跡速度の階段(役職ごとの `drain_per_second`)を、そのまま残す |
| 12 | 記録・スコア | 記録の形・版(3)・スコアの式は、変えない。**残り距離がスコアに入る(×5)ので、以前の記録と、少し尺度が変わる**(役職ごとの `base_gain` が変わったため)。ランキングは、この端末の中だけ | 0022 と同じ注意 |

## バランス(実際の語録・エンジン・打鍵の 4 モデル・各 4000 回。クリア率 %)

打鍵のモデル: ふつう = 2.5 打鍵/秒・ミス 8%、遅い = 1.2・8%、速い = 4・5%、達人 = 6・3%。**打鍵ごとに時間を進める**(ミスの時刻で、ルールの加速の間が決まるため)。現行の値を、この方法で測り直しても、これまでの表と、ほぼ同じ(先輩 87・係長 90・部長 66・社長 49・会長 75)で、方法は、これまでと同じ信頼で使える。

| 役職 | 遅い | ふつう | 速い | 達人 |
| ---- | ---- | ------ | ---- | ---- |
| **A. 現行(ルールなし・重みなし)** | 先輩 87 | 係長 90 / 部長 66 / 社長 49 | 会長 75 | 100 |
| B. 重みとルールを足して、`base_gain` はそのまま | 先輩 96 | 係長 74 / 部長 28 / 社長 10 | 会長 28 | 100 |
| C. 重みだけ(ルールなし)、`base_gain` はそのまま | 先輩 96 | 係長 92 / 部長 66 / 社長 42 | 会長 69 | 100 |
| **D. 採用**(重みとルール・`base_gain` を調整) | **先輩 86** | **係長 89 / 部長 67 / 社長 48** | **会長 76** | **100** |

- 先輩は、短い語が出やすくなり、B・C で 87 → 96 に上がるので、`base_gain` を下げた(3.9 → 3.3)。ほかの役職は、ルールで下がる分を、`base_gain` で戻した
- **頑健さ**: 打鍵の速さに ±20% のばらつきを入れても、先輩(遅い)83・係長 87・部長 64・社長 45・会長(速い)74(目標から 4 ポイント以内)。**ミスの多い人への厳しさは、これまでとほぼ同じ**(ふつうの速さで、ミス 14%: 係長 28・部長 7・社長 2。ルールなしの現行は 27・6・2)
- 所要時間: 先輩(遅い)約 107 秒、ふつう 約 58〜70 秒、達人 27〜36 秒(1 プレイ 1〜3 分)
- これは、**モデルの打鍵での目安**。実際の人間の手ごたえは、未確認(遊んで、あなたが調整する。数値は `roles.json` だけで直せる)
- `tests/balance.test.js` も、同じ方法(打鍵ごと・役職の重み・ルール)に更新した。新しく、「役職が進むほど、語が長くなる」「ルールを外すと、クリア率が上がる」を検査する
