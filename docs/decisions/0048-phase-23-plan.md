# 0048 Phase 23 の計画(役職ごとのBGM・効果音・全演出スキップ・セリフ設定・音の環境設定点検)

日付: 2026-09-25 / 対象: Phase 23「BGMは職種・役職・状況で変化。役職別効果音。全演出スキップと自動スキップ。セリフ速度・表示時間設定。音量・品質・アニメーション軽減。」

「自立で」という運営者の指示(フェーズ移行も含む)により、実装前の確認を待たず、計画・実装方針を Claude Code の判断で決定した。

## 現状の確認

- 音は、Web Audio で合成する固定の1パターン(BGM: 4小節・低音+メロディー。効果音: start/correct/miss/near/clear/over の6種類)。役職・職種・状況による違いは、まだない。CLAUDE.md には「職種・役職ごとのBGM・役職別の効果音・演出のスキップ設定は、Phase 23」と、あらかじめ書いてある(Phase 16 PR3 時点での予告)
- `roles.json` は、すでに役職ごとに `scene.motion`(動き)・`scene.outro`(終わりの演出)・`lines`(セリフ)を持つ、データ駆動の設計。**同じ考え方で、音の個性も、役職ごとの数値(倍率)として持たせる**のが、既存の設計と一貫する
- 演出のスキップは、すでにある(`staging.js` の `timeline.skip()`。Enter・スペース・Esc・場面のクリックで、手動で飛ばせる)。**「全演出スキップ」は、これを自動化する、新しい設定**だと判断した
- セリフの間隔(`lines.js` の `gapMs`)・表示時間(`main.js` の `BUBBLE_MS`)は、**すでに関数の引数として渡せる設計**(依存注入)。値を固定で使っているだけなので、設定から渡すだけで対応できる
- 音量(`settings.js` の `volume`)・アニメーション軽減(Phase 21 の `motion.js`)は、すでにある。「品質」だけが、新しい要素

## この PR(1)の決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 「役職」による変化 | `roles.json` の各役職に、新しい `sound: { tempo, pitch }`(倍率。既定に近い 1.0 前後)を追加。`tempo` は BGM の速さ、`pitch` は BGM・効果音の高さの倍率。**役職が進むほど、わずかに速く・高くなる**(先輩 1.0/1.0 → 会長 1.2/1.1 程度)。既存の「役職が進むほど難しくなる」(0006決定ログ)設計に、音でも寄り添う | `roles.json` に、動き・演出・セリフと同じ形で追加でき、既存の設計と一貫する。倍率は控えめにし(最大20%程度)、不快な速さ・高さにならないようにする |
| 2 | 「状況」による変化 | 「危ない」状態(`isDanger`)の間、BGM の速さに、追加の倍率(`DANGER_TEMPO_BOOST`)をかける。危なくなくなったら、元に戻す。効果音の高さは変えない(BGMの速さだけ) | 既存の「危ない」判定(`isDanger`。ゲージ・場面・合図で、すでに共通して使っている)を、音でも再利用する。新しい判定を増やさない |
| 3 | 「職種」による変化 | **この PR では対応しない**(既知の制限)。職種ごとに異なる旋律を作ることは、6職種分の作曲という、大きなコンテンツ制作になり、この案件のデータ駆動・パラメータ調整という設計方針(役職の速さ・音の高さのような、数値の調整)を超える。職種の個性は、すでに背景の絵(Phase 15)で出している | 仕様書にない機能を、勝手に大きく増やさない(`.claude/CLAUDE.md` の方針)。音楽の作曲は、確認・調整が難しく、AIの下書き→人間の確認、という語録・セリフと同じ流れを踏める性質のものでもない |
| 4 | 役職別効果音 | 効果音(`SOUND_EFFECTS`)の周波数(`hz`・`to`)に、役職の `pitch` 倍率をかけて鳴らす(`effectNotes(name, pitch)`)。**音の種類・長さ・音色(wave)は変えない**(役職ごとに全く別の音を作ると、6役職×6種類=36通りの調整・確認が必要になり、過大)。高さだけを、役職に応じてずらす | 役職ごとの個性を、少ない変更で、聞き分けられる形で出す。既存の6種類の効果音の設計(Phase16 PR3)を壊さない |
| 5 | 実装の場所 | `sound.js`(純粋な計算)に、倍率を受け取る形に変更。`audio.js`(鳴らす係)に、`setRoleSound({ tempo, pitch })`(ゲーム開始のたびに1回。危ない状況の倍率もリセットする)・`setDanger(bool)`(状況による、一時的な倍率)を追加。`configure({ mode, volume })` とは別のメソッドにする(音量・モードの設定変更と、役職の音の個性は、変わる頻度・きっかけが違うため)。`main.js` は、`beginGame` で `sound.setRoleSound(roleSoundOf(role))`、危ない状態の変化ごとに `sound.setDanger(danger)`、`quit` で `sound.setRoleSound()`(既定に戻す)を呼ぶ | 既存の層分け(データ計算・鳴らす係・画面のつなぎ)を保つ。`configure` は既存のテスト・呼び出し側が多いため、シグネチャを変えず、新しい関心ごとは、新しいメソッドに分ける |
| 6 | 検証・データの形 | 新しいファイル `role-sound.js`(DOM・音に触れない純粋関数)に、`DEFAULT_ROLE_SOUND`・`roleSoundOf(role)`(役職から安全な倍率を取り出す。ない・壊れていれば既定)を置く。`roles.json` の全役職に `sound` を追加し、テストで検証する | `scene.js`・`outro-styles.test.js` と同じ、データの検証を独立させる設計を踏襲する |

## この PR(3)の決定

### 現状の確認(着手前の点検)

- **音量**(`settings.js` の `volume`。0〜100)は、Phase16 PR3 からすでにあり、UI(スライダー・数値表示)・保存・`masterGain` による2乗カーブの反映まで、動作済み。Phase 23 PR1(役職の tempo/pitch)・PR2(セリフ設定)を追加したあとも、`sound.configure({ mode, volume })` の経路は変えていないため、影響はない。**変更不要**
- **アニメーション軽減**(Phase 21 PR1〜2 の `motion.js`。`prefersReducedMotion()`)は、`staging.js` の `introSteps`/`outroSteps`・CSS の `animation-duration` 上書きで、すでに一貫して反映されている。Phase 23 PR1(BGMの速さ)は音の設定であり、動きの設定とは独立(意図的に別軸。CLAUDE.mdの「グラフィックを抑える」の記述と同じ考え方)。Phase 23 PR2 の「演出を自動で飛ばす」は、動きを減らす設定と**役割が重なる**ように見えるが、「動きを減らす」は演出を短くするだけで、飛ばしはしない(意図した見た目の差を、完全にはなくさない)、「演出を自動で飛ばす」は、時間に関わらず即座に飛ばす、という異なる目的の設定であるため、共存させたままにする。**変更不要**
- **「品質」**: Web Audio 合成(ファイルなし)という設計上、一般的な音声の「ビットレート」のような概念はない。低性能端末向けに意味があるのは、**同時に鳴らすオシレーター(音源)の数を減らし、スケジューリングの負荷を下げること**だと判断した。現在の BGM(`sound.js` の `bgmStepNotes`)は、拍ごとに、低音(BASS)とメロディー(MELODY)の**最大2つ**のオシレーターを同時に予約している。これを、低性能端末向けに、低音だけ(1つ)に減らせるようにする

### 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 新しい設定 | `settings.js` に `simpleSound`(既定オフ)を追加。**`simpleGraphics`(グラフィックを抑える。Phase22 PR3)とは、別の設定にする** | 視覚と聴覚は別の感覚で、低性能な端末でも、片方だけ簡略化したい場合がありうる(例: 描画は重いがCPUに余裕がある/その逆)。CLAUDE.mdの「グラフィックを抑える」の説明文も、視覚の要素(背景・紙吹雪・輝き)に限定しており、音を混ぜると、チェックボックスの名前と効果が一致しなくなる |
| 2 | 簡略化の中身 | ONのとき、BGMは、低音(BASS)だけを鳴らし、メロディー(MELODY)を鳴らさない。効果音(SE)は変えない(もともと最大4音・1.5秒以内の短いもので、負荷が小さいため) | BGMは、常時・連続してオシレーターを予約し続ける(効果音は、単発)。ここを減らすことが、低性能端末への効果が最も大きい。音色・音の大きさ・テンポ(役職の個性)は変えず、**同時に鳴る音の数だけ**を減らす |
| 3 | 実装の場所 | `sound.js` の `bgmStepNotes(step, pitch, simple)` に、第3引数 `simple`(既定false・後方互換)を追加。`true` のとき、MELODYの音符を追加しない。`audio.js` の `configure({ mode, volume, simple })` に `simple` を追加し、`tickBgm()` が `bgmStepNotes(bgmStep, rolePitch, simple)` を呼ぶ | 既存の `pitch` 引数(Phase23 PR1)と同じ、依存注入・後方互換のパターンを踏襲。`configure` は、すでに音量・モードをまとめて反映する入口なので、同じ「音の鳴らし方の設定」として、ここに合流させる(`setRoleSound`・`setDanger` は、役職・状況という別の関心ごとなので、混ぜない) |
| 4 | 画面 | ダッシュボードの音の設定欄(`data-sound-option`)の中、音量の下・「音を試す」の上に、チェックボックス「BGMを簡略化する(低性能な端末向け)」(`data-simple-sound`)を追加。**用語確認でも隠さない**(音の設定欄=`data-sound-option`自体が、いまも両モードで表示されているため) | 既存の音の設定欄に自然に収まる位置。音の設定は、モードに関わらず、いつでも変更できる既存の一貫性を保つ |
| 5 | 除外 | 効果音の音数を減らす・BGMのテンポを落とす・サンプルレートを下げる、は対象外 | 効果音は、もともと軽量。テンポは、役職の個性(Phase23 PR1)そのものであり、低性能端末向け設定で上書きすると、役職の判別がつきにくくなる。Web Audioの内部サンプルレートは、ブラウザの管理下にあり、アプリ側から安全に下げる標準的な方法がない |
