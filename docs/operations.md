# 運用・障害対応の手順(運営者向け)

Phase 28。サイトに問題が起きたときの、**気づき方・止め方・戻し方・確認の仕方**を、1か所にまとめました。細かい手順は、それぞれの文書へリンクしています。決定は `docs/decisions/0053-phase-28-plan.md`。

## 1. 気づく方法(いまの体制)

外部の監視サービス(有料・第三者への送信を伴うもの)は、**入れていません**(規約・費用・プライバシーを確認してから導入する方針。導入するときは、決定ログとポリシーを確認する)。いま使えるのは、次の 3 つです。

| 方法 | 内容 |
| ---- | ---- |
| GitHub Actions | `main` への反映と PR ごとに、CI(`npm run check`・`npm run audit`)が動く。失敗すると、GitHub から通知が来る |
| Cloudflare のダッシュボード | Pages → **Deployments**(ビルドの成否)・**Functions** のログ・D1 の状態を見る(画面の名前は、変わることがある) |
| `npm run smoke` | 公開したサイトの簡易チェック(下の「3. 確認」) |

- サーバーの想定外のエラーは、`/api/*`・`/auth/*` の共通処理が、**詳しい内容をログにだけ出し**、利用者には `server-error`(JSON)を返す。ログには、メールアドレス・問い合わせの内容を出さない(`CLAUDE.md`)。
- 利用者からの連絡は、`/support/` の問い合わせ(`npm run inquiries` で読む。`docs/contact-setup.md`)。

## 2. 症状ごとの対応

まず**止める**(被害を広げない)→ **戻す**(サイトを直前の状態へ)→ **確認する** → **記録する**、の順です。

| 症状 | 止める・戻す | 詳しい手順 |
| ---- | ---- | ---- |
| 公開した変更で、画面・動きが壊れた | Cloudflare → Pages → **Deployments** → 以前の本番デプロイ → **Rollback**。そのあと、原因の変更を **Revert の PR** で戻す(`main` に、直接コミットしない) | `docs/release-process.md` |
| ログイン・アカウントに問題がある | 環境変数 `AUTH_ENABLED` を `false` にして再デプロイ(ログイン・API だけが止まる。静的ページとデータは、そのまま) | `docs/auth-setup.md` |
| 問い合わせフォームに、ボットが殺到した | 環境変数 `CONTACT_ENABLED` を `false` にして再デプロイ(フォームは「準備中」。保存済みの内容は、残る) | `docs/contact-setup.md` |
| 知らない人がアカウントを作っている | `SIGNUP_MODE` が `invite` か確認する(許可リスト `ALLOWED_EMAILS` にないメールは、作れない)。必要なら `AUTH_ENABLED` を止める | `docs/auth-setup.md` |
| データベースを、間違って変えた・消した | 7 日以内は D1 の Time Travel。それより前・DB ごと失ったときは、書き出したファイルから | `docs/backup.md` §4 |
| 秘密(`GOOGLE_CLIENT_SECRET`・`SESSION_SECRET`)が漏れたかもしれない | Google と Cloudflare で、その値を新しく作り直し、再デプロイする。`SESSION_SECRET` を変えると、**全員のログインが切れる**(記録は残る) | `docs/auth-setup.md` |
| ビルド(Cloudflare Pages)が、失敗し続ける | 本番は、前のデプロイのまま動き続ける(壊れない)。ダッシュボードのビルドのログを見て、原因の PR を Revert する | — |

- **ロールバックは、サイトのファイルだけを戻す**。D1 のデータ・環境変数は戻らない。`migrations/` を含む変更を戻すときは、新しい列・テーブルが残っても、古いコードが動くか確認する(`migrations/` の既存ファイルは書き換えない)。
- 環境変数を変えたら、**再デプロイ**が要る(変えただけでは、反映されない)。
- 対応の途中で、**バックアップの SQL・秘密の値を、GitHub・チャットに貼らない**(`docs/backup.md`)。

## 3. 確認する(デプロイ後・ロールバック後・復元後)

```
npm run smoke -- https://nolito-jukiii.com
```

- 主要なページが 200 で開けること・存在しないページが 404 になること・`/api/me` と `/api/products` が JSON を返すこと・画像のキャッシュ期間(1 日)・**同意の前に、ページが Google のアクセス解析を読み込まないこと**を見る。
- 1 件でも問題があれば、終了コード 1。遅い(3 秒超)ページには「(遅い)」と出る(失敗にはしない)。
- 中身を読むだけで、何も送らない・書き換えない。プレビューの URL(PR ごとの `https://<英数字>.nolito.pages.dev`)にも使える。
- 自動では、確認できないもの(実機のブラウザでの表示・スマホ・キーボード操作・読み上げ)は、`docs/05_checklists/release-checklist.md` の手順で、目で見る。

## 4. 記録する

障害があったら、落ち着いてから、`docs/decisions/` に、次を書く(責める文書ではなく、次に同じことを防ぐための記録)。

- 何が起きたか(いつ・どの機能・影響した範囲)
- 何をして直したか(止めた・戻した・直した)
- 原因と、再発を防ぐために変えること(テスト・手順・設定)
- 個人情報が、外に出た可能性があるとき: 影響を受けた人・**プライバシーポリシーの版を上げるか**(`CLAUDE.md`)の判断

## 5. まだ入れていないもの(必要になったら、範囲を決めてから)

- エラーの自動通知(メール・チャット)・外部の稼働監視。無料の範囲・第三者への送信の有無・ポリシーへの影響を、先に確認する。
- Core Web Vitals の実際の利用者データでの計測。同意した人だけの Google Analytics の範囲で扱うか、別の方法にするか、決めてから。
