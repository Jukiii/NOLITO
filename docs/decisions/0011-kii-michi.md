# 0011 最初のツール「キーみち」(PR 1: 登録・ルート・一覧・チートシート)の決定事項

日付: 2026-09-20 / 対象: Phase 8 の基盤(0010)の上の、最初のツール。Issue #15 のコメントが企画。

## 企画(Issue #15)

「キーボード操作ルート設計」。キーボードだけで作業するためのキー操作ルートを考える。機能: 使用アプリの選択、よく使う操作の登録、ショートカット一覧の作成、操作順の練習モード、自分用チートシートの出力。珍しいポイント: ショートカット辞書ではなく、自分の作業手順に合わせて操作ルートを組み立てる。全部無料。保存は browser。

## スコープ

- **PR 1(この決定)**: アプリ・操作の登録、ルートの組み立て、ショートカット一覧、チートシート(印刷・Markdown)、設定(キーの表記・JSON の書き出し/読み込み・全削除)。「テスト版 0.1.0」として公開し、ナビの「ツール」を有効にした
- **PR 2(次)**: 練習モード(操作順の練習)。「0.2.0」として公開する
- 含めない: ショートカット辞書・見本データの同梱(質問3の決定)、練習モードの履歴・成績(仕様にない)、アカウントへの保存(P9・P19)、複数人での共有(チーム。P26)

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 名前・場所 | 名前「キーみち」、id `kii-michi`、URL `/tools/kii-michi/`(詳細ページ `/tools/kii-michi/about/`)。カテゴリ tool、状態 beta、版 0.1.0 | 企画の名前案どおり |
| 2 | 辞書は作らない | アプリごとのショートカットを同梱しない。利用者が、自分のアプリ・操作を登録する | OS・バージョン・設定で違い、正確さを保てない(語録のような「AIの下書きを人間が確認」も要る)。「辞書ではなく自分の手順」という差別化とも合う |
| 3 | データ | `apps`・`operations`(アプリ・名前・キー(順に押す最大4つ)・メモ)・`routes`(名前・メモ・手順=操作の id の並び。同じ操作を何度でも)・`settings.os`。上限: アプリ50・操作500・ルート50・1ルートの手順50・名前60字・メモ200字。保存の部品(0010)に、`normalize`(`normalizeData`)を渡して、保存・読み込み・取り込みのたびに検査する | 取り込むファイルは書き換えられるので、件数・文字数・参照(存在しない id)・キーの形を、すべて検査する。不正なら、保存データは `:corrupt` に退避され、取り込みは拒否される |
| 4 | キーの扱い | キー操作は `{ ctrl, alt, shift, meta, key }`。`key` は英字(小文字)・数字・F1-F12・名前つきのキー(Enter など)・記号 `` ` - = [ ] \ ; ' , . / ``。**押したキーは、印字ではなく位置(`event.code`)で読む**。記号のラベルは US 配列。文字での入力は、大文字小文字・別名(Control・Option・Command・Win・Esc・矢印の記号など)・全角スペース・「 → 」区切り・末尾のカンマを許す。「Ctrl+,」のカンマは、キーとして読む | Shift や配列の違いで、同じキーが別の値になるのを避ける。表記と解析は、全キー・全修飾キー・両 OS で、往復が一致することをテストしている。JIS 配列では、記号の印字が違う場合がある(既知) |
| 5 | OS の表記 | 設定で Windows(Ctrl / Alt / Shift / Win)と macOS(Control / Option / Shift / Command)を切り替える。切り替えで変わるのは表記だけで、登録した操作の中身は変わらない。初回は、端末から自動で判定する | Windows と Mac で、キーの意味が 1 対 1 に対応しない場合があるため、変換はしない。利用者は、自分の環境で登録する |
| 6 | 「キーを押して入力」 | 押した1つ分を、入力欄に足す(順に押すときは、もう一度押す)。**Esc で中止**。ほかの場所のクリックでも終わる。修飾キーだけの押下は無視して、記録を続ける。対応していないキーは「記録できません」と案内。日本語入力(IME)の変換中は判定せず、警告する。記録中は、押したキーの既定の動作(F5 での再読み込みなど)を止める | キーボードだけで使うツールなので、キーボードトラップ(WCAG 2.1.2)を作らない。IME は、ゲームと同じ方針 |
| 7 | 押せないキー | Ctrl+W・Ctrl+T・Alt+F4・Win キーなど、ブラウザ・OS が先に処理するキーは、押すと、タブが閉じるなどして、ページは止められない。入力欄の説明で「文字で入力してください」と案内し、文字で入力すれば登録できる。文字で入力した、そのようなキーには、プレビューで「先に処理するキーです(登録はできます)」と注意を出す。一覧(`reservedReason`)は目安 | 仕様に反しない範囲で、判定できないことを、正直に見せる。練習モード(PR 2)は、このキーを「自己確認」にする |
| 8 | チートシート | ルート・アプリ別の一覧を選んで載せる。**印刷**(ブラウザの印刷。PDF に保存もできる。印刷では、チートシート本体だけを白い紙に出す)、**Markdown のコピー**(権限がなければ、下の欄を開いて案内)、**`.md` ファイルの保存**。画面と Markdown は、同じ元データ(`sheetModel`)から作る | 企画の「自分用チートシート出力」 |
| 9 | Markdown の安全性 | 名前・メモの、強調・リンク・HTML・表・コード・実体参照の記法は、バックスラッシュで打ち消す(行頭でだけ意味を持つ `# - + > =` と「1.」は、行頭のときだけ)。改行は空白にする。キーが `` ` `` を含むときは、コードの囲みを長くする。画面は `textContent` だけで表示する | 利用者が入力した文字が、他のアプリで、見出し・リンク・HTML として読まれない |
| 10 | 保存 | 企画の `browser` に加えて、**JSON の書き出し/読み込み(`file`)**を付けた(質問4の決定)。読み込みは、置き換えの確認を出し、置き換え前のデータを `:before-import` に退避する(0010)。読み込みの失敗は、理由(JSONでない・別のツール・新しい版・中身が不正・大きすぎる)を表示する。「設定」で全削除もできる(確認つき) | サイトデータを消しても、ルートを取り戻せる |
| 11 | 保存の異常の案内 | 壊れたデータ・新しい版のデータ・保存できない環境(localStorage が使えない)・容量超過・**ほかのタブが保存を変えた**(このタブの画面が古くなる)を、画面の案内で知らせる。ほかのタブの変更は、上書きの警告を出す(自動では、マージしない) | 利用者のデータを、黙って失わない |
| 12 | アクセシビリティ | タブは WAI-ARIA のタブ(矢印・Home・End・ロービング tabindex)。すべての入力・ボタンに名前(ラベル・aria-label)。手順のボタンには、番号と操作名を含む名前(「3番目「コメント」を1つ前へ」)。間違いは `role="alert"`・`aria-invalid`・太字と印(色だけに頼らない)。操作の結果は、読み上げ用の領域で通知。破壊的な操作は、確認のダイアログ(フォーカスの初期位置は「キャンセル」。Esc で閉じ、フォーカスは元のボタンに戻る)。追加・削除・移動のあとは、フォーカスを次の操作の場所へ。ボタン・タブの高さは 44px 以上。画面幅 375〜1280px で、横スクロールなし | キーボードだけで使うツール |
| 13 | 広告の枠・計測 | 広告の枠は置かない(操作の画面)。計測は、サイトの共通(ページビューのみ)のまま | 広告は Phase 29。ツールの操作の内容は、計測しない |
| 14 | プライバシーポリシー | §2 に、ツール(例:「キーみち」)が、入力した内容を、端末の中にだけ保存し、送信しないことと、書き出したファイルの取り扱いを追記した。**版は上げない**。あわせて `CLAUDE.md` の「ポリシーを変えたら版を上げる」を、「同意に関わる内容(計測・外部送信・保存期間・第三者提供)を変えたら」に明確にした | 版は、計測(GA)の同意を取り直すためのもの。今回は、計測の内容・外部への送信・保存期間のどれも変わらず、端末内の保存の説明を足しただけ。版を上げると、全員に、不要な再確認を求めることになる |
| 15 | 商品データ | `products.json` に追加。説明・詳細・画面3枚(実際の画面。見本のデータは、広く知られたショートカットだけ)・動作環境・FAQ7件・更新履歴・`storage: ["browser","file"]`・`plan`(すべて無料)。表紙は、SVG のイラスト。サイト紹介にも追加 | 動作環境には、確認した範囲(Edge・Windows)だけを書いた(運営者が、あとで書き換える) |

## 未確認・既知事項

- **確認したのは Microsoft Edge(Windows・headless)だけ**。macOS・ほかのブラウザ・実機のキーボード(JIS 配列を含む)・スマートフォン・タブレットは未確認。JIS 配列では、記号キーの印字が、ラベル(US 配列)と違う場合がある
- **スクリーンリーダー(NVDA・VoiceOver など)での実際の読み上げは、未確認**。DOM・ARIA・読み上げ用の領域の内容は確認したが、実際の音声は聞いていない
- 実際の印刷ダイアログ・紙への印刷は未確認(印刷用の表示と PDF の生成まで)
- ブラウザ・OS が先に処理するキーの一覧は、目安(ブラウザやバージョンで違う)。練習モード(PR 2)で、判定の限界を、利用者に見せる
- 詳細ページの文面・FAQ・動作環境は、私が起こした下書き。運営者の確認が必要
- 複数のタブの同時編集は、案内(上書きの警告)までで、マージはしない
