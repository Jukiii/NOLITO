# 問い合わせフォーム(Phase 10)の設定と運用

運営者(あなた)向けの手順です。フォームは、設定がそろうまで、何もしません(`/support/` には「準備中」と表示されます)。

## しくみ

- 利用者が `/support/` のフォームから送ると、内容が、本番の D1(`inquiries` テーブル)に**保存**されます。
- **メールは、送られません。**(メールの通知は、独自ドメインを決めてから足します。) あなたが、手元のコマンドで、**読みに行きます**。
- 返信が必要な場合は、利用者が入力した返信用のメールアドレスに、あなたのメールソフトから、お返事します(入力がなければ、返信できません)。

## 1. 有効にする(1回だけ)

1. **D1 にテーブルを作る**: `docs/auth-setup.md` の「D1 に貼る SQL」の **0003** を、すべてコピーして、D1 の Console に貼り、実行します(**Tables** に `inquiries` が増えれば成功)。
   - **PR をマージする前**に、実行してください。
2. **環境変数を1つ足す**(Cloudflare → Pages → **Settings** → **Variables and Secrets** → **Production** → **Add**):

   | 名前 | Type | 値 |
   | ---- | ---- | ---- |
   | `CONTACT_ENABLED` | Text | `true` |

   - 必要な `DB` のバインディング・`SESSION_SECRET`・`SITE_ORIGIN` は、アカウント機能の設定(`docs/auth-setup.md`)で、すでに入っています。**Google の設定は、要りません。**
3. **再デプロイ**する(**Deployments** → 最新の本番デプロイ → **Retry deployment**)。
4. **確認**:
   1. `https://nolito.pages.dev/api/contact` を開く → `{"enabled":true}` と出る(`false` なら、手順1・2・3のどれかが足りません)。
   2. `https://nolito.pages.dev/support/` を開く → フォームが出る。
   3. 自分で、テストの内容を送る(種類・内容を入れて「送信する」)。
   4. 手元で `npm run inquiries` を実行 → 今送った内容が出る。
   5. `npm run inquiries -- --done <ID>` で、対応済みにする。

### 止めたいとき

`CONTACT_ENABLED` を `false` にして、再デプロイします(フォームは「準備中」になります。保存済みの内容は、残ります)。

## 2. 日々の運用

メールの通知がないので、**週に1回くらい**、見に行ってください(カレンダーのリマインダーがおすすめです)。

準備(初回だけ)は、`docs/backup.md` の「準備」と同じです(`npx wrangler login` と、環境変数 `NOLITO_D1_DATABASE_ID`)。

| やりたいこと | コマンド |
| ---- | ---- |
| 未対応の問い合わせを読む(新しい順) | `npm run inquiries` |
| 対応済みも含めて読む | `npm run inquiries -- --all` |
| 対応済みにする | `npm run inquiries -- --done <ID>` |
| 消せるもの(対応済みで、180日以上たったもの)の件数を見る | `npm run inquiries -- --purge` |
| それらを、削除する | `npm run inquiries -- --purge --yes` |

- 表示される **ID** は、各問い合わせの1行目の下にあります。
- 返信は、表示された「返信先」のメールアドレスに、あなたのメールソフトから送ります。
- **月に1回**、バックアップ(`npm run backup:d1`)の前後に、`--purge` で、古い問い合わせを削除してください(保管の約束: 対応が終わってから約6か月)。

## 3. 個人情報の扱い(守ること)

問い合わせには、個人情報(本文・メールアドレス)が入っています。プライバシーポリシー(版 2)に書いた約束を、守ってください。

- 内容は、**端末に表示するだけ**です。ファイルに書き出さず、スクリーンショットや、チャット・GitHub には、貼らない(私(Claude)に、貼るときも、個人情報は、伏せてください)。
- **保存は、対応が終わってから約6か月**。`--purge` で、削除します。バックアップにも残るので、バックアップも、6か月分までにします(`docs/backup.md`)。
- **開示・訂正・削除の請求**が来たら、対応します。すぐに消すときは、D1 の Console で、次の SQL(`ここにID` は、一覧に出た ID)を実行します(1文ずつ、コメントなし)。

  ```sql
  DELETE FROM inquiries WHERE id = 'ここにID';
  ```

- 表示するとき、端末の制御文字は、`?` に置き換えています(外の人が書いた内容で、画面を書き換えられないように)。
- サーバーのログ・監査ログには、問い合わせの内容・メールアドレスを、残していません(種類だけ)。

## 4. スパム対策

| しくみ | 内容 |
| ---- | ---- |
| 罠の欄 | 人には見えない欄が埋まっていたら、保存しない(ボットには、成功したように見せる) |
| 最短の時間 | ページを開いてから、3秒未満の送信は、保存しない |
| 回数の制限 | 1つの送信元(IP)から、1時間に3件まで。全体でも、1日100件まで(洪水で、D1 の無料枠を使い切らないため) |
| 大きさ | 本文は 10〜2000 文字。本体は 16KB まで |
| 文字 | 制御文字・双方向制御文字は、断る |

- **Cloudflare Turnstile(外部のスクリプト)は、使っていません。** スパムが増えたら、そのとき、追加を検討します。
- 全体の上限(1日100件)に、ボットが達すると、**正しい問い合わせも、その日は、受けられなくなります**。そうなったら、`CONTACT_ENABLED` を止めるか、Turnstile の導入を、ご相談ください。

## 5. まだないもの

- メールの通知(独自ドメインを決めてから)
- 自動返信メール
- 問い合わせの管理画面(Phase 26 以降)
