# 0087 記事の管理画面(入力フォーム・本文のプレビュー)

- 日付: 2026-10-03
- 関連: Issue #195(PR 2)・#162・決定 0086

## 経緯

Jさんが、記事の管理は管理画面で行うことを選んだ(#162・#195「A」)。0086 で D1 と API を作ったので、この PR で、画面を作る。プロダクトの管理画面のような「JSON をそのまま書く」形ではなく、記事を書く人が使う**入力フォーム**にする。

## 変えたこと

- `/account/admin/articles/`(`noindex`): 一覧(編集・削除)、フォーム(スラッグ・題名・説明・日付・タグ・公開の状態(下書き/公開)・本文(Markdown))、本文のプレビュー、削除の確認(モーダル)。
  - スラッグは、新規のときだけ入力できる(更新では変えられない。0086)。タグは読点(、)かカンマで区切る(`admin/article-form.js` の `parseTags`)。新規の日付の初期値は今日。
  - 保存・削除は 0086 の管理 API。サーバーの検証の文(`details`)を、そのまま表示する。削除は、直近 10 分のログインが要る(`reauth-required` のときは「もう一度ログインする」を出す)。
- **プレビュー API `POST /api/admin/article-preview`**(`requireAdmin`・CSRF つき)。本文を、公開と同じ変換(`renderMarkdown`)で HTML にして返すだけ。**何も保存せず、監査ログも書かない**。不正な本文は `400 invalid-article`(`details` つき)。検証と変換は `articles/_shared.js` の `renderArticleBody` に集め、保存の検証と同じ規則にした。
- **プレビューの表示は `admin/preview.js`**: サーバーが返した HTML を、さらに、許可した要素・属性だけで作り直して表示する(`innerHTML` は使わない)。リンクはサイト内・#・http・https・mailto、画像はサイト内・https だけ。許可は `ALLOWED` にあり、script・iframe・style・`on*` 属性は入らない(テストが検査)。サーバー側の変換が安全でも、画面側でもう一度絞る(多重の防御)。
- 管理画面のトップと、すべての管理ページの `admin-nav` に「記事の管理」のリンクを足した。

## 変えないこと

- 公開の記事ページ・一覧・検索・更新履歴・`npm run build:articles`(PR 3 まで静的ファイルが元)。ここで保存した記事は、いまは管理画面の中だけにある(画面にも、その旨を書いた)。
- API・D1 の形・プライバシーポリシーの版。
