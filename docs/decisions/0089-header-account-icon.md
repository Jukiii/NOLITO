# 0089 ヘッダーに、ログイン状態で変わるアカウントのアイコンを置く

- 日付: 2026-10-03
- 関連: Issue #173・決定 0013(アカウント)・0043

## 経緯

Jさんが Issue #173 で、「サイト全体のトップバーに、ログインしているかどうかで変わるアイコンが欲しい。そこから `/account/` に行けるように」と依頼した。これまでは「フッター・ナビに『アカウント』を出すのは、一般公開のとき(いまは `/account/` は `noindex` で、リンクなし)」としていた。この決めは、Jさん本人の依頼で、ヘッダーのアイコンについては置き換える(招待制のままでも、運営者・招待された人が行き来しやすくするため)。

## 変えたこと

- ヘッダー(`components/header.js`)の右端に、`components/account-link.js` のリンク(`.site-account`)を足した。ハンバーガーのパネルの外にあるので、モバイルでも、いつも見える。リンク先は `/account/`。
- ログイン中 = 塗りつぶしの人型、未ログイン = 枠だけの人型。**色だけに頼らない**: PC では「アカウント」「ログイン」の文字を添え、モバイルでも、読み上げの文(`aria-label`)が「アカウント(ログイン中)」「ログイン(アカウントのページへ)」と変わる。アイコンは CSS だけで描く(`el()` は HTML の要素だけを作るため、SVG は使わない。色はトークン経由)。
- ログイン状態は、`/api/me`(`account/client.js` の `fetchMe`)で、ページを開くたびに 1 回確かめる。確認の間は、場所だけ確保して見せない(`visibility: hidden`。レイアウトがずれない)。
- **アカウント機能がない環境(`enabled: false`・プレビュー・通信の失敗)では、アイコンを隠す**(押しても、使えないページに行くだけのため)。ヘッダーは壊れない。

## 変えないこと

- ログイン状態を、端末(LocalStorage・Cookie の読み取り)に置かない。毎回サーバーに聞く。
- プライバシーポリシーの版は上げない。同じサイト内の `/api/me` を、すでにあるセッションの Cookie で呼ぶだけで、新しい情報の取得・外部への送信はない(同意に関わる内容の変更ではない)。
- `/account/` の `noindex`・招待制・一般公開の前提(Issue #19)。ナビ(`config/nav.js`)の項目は変えていない。

## 既知の制限

- ページを開くたびに `/api/me` が 1 回増える。
- `/account/` でログアウトしても、別のタブのヘッダーのアイコンは、次にページを開くまで、そのまま。

## テスト

- `tests/account-link.test.js`: 状態の判断・文字と読み上げの切り替え・機能が無効/失敗のときに隠れる・ヘッダーへの組み込み・保存や `innerHTML` を使わない・タップの大きさ・`[hidden]` が効く・色の直書きがない。
- ヘッドレスの Edge と、`/api/me` を模擬するサーバーで、幅 500px と 1280px の、未ログイン・ログイン中・機能なしを確認(横にはみ出さない・タップ 44px 以上・ハンバーガーが開く・機能なしでは大きさ 0)。
