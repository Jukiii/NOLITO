# 0012 キーみち PR 2: 練習モードの決定事項

日付: 2026-09-20 / 対象: 最初のツール「キーみち」(0011)の PR 2。企画(Issue #15): 「操作順の練習モード」。

## スコープ

- **含める**: 練習の画面(ルートを選んで、手順を順番どおりに、キーを押して練習する)、判定できない手順の自己確認、結果の表示。「0.2.0」として公開する
- **含めない**: 練習の履歴・成績(仕様にない。結果は保存しない)、苦手な手順だけの再練習(仕様にない)、手順の並べ替え・ランダム出題、時間の計測

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 練習の進め方 | 「練習」の画面(ルートの次のタブ)と、ルートの画面の「このルートを練習する」から始める。手順を順番どおりに1つずつ出し、アプリ名と操作名を見せて、**キーは隠す**。キーを押すと判定して次へ。ヒント(答えを見る)・スキップ・やめるができる。順に押すキー(Ctrl+K → Ctrl+C)は、1つずつ照合して、進み具合を案内し、間違えたら最初から。途中で最初のキーをもう一度押したら、そこから数え直す。最後に、結果の表(手順ごとの、キー・答え方・結果・間違い・答えを見たか)と、「もう一度」 | 企画の「操作順の練習」 |
| 2 | 練習の写し | 開始時のルートの手順を写して進める。練習中に、操作やルートを変えても、練習は変わらない。データを入れ替える操作(取り込み・全削除)をしたら、練習は終わる | 練習中の手順が、突然変わらないように |
| 3 | 結果は保存しない | その場の結果を、終了時に表示するだけ。保存の形・版は変えない(移行なし) | 履歴・成績は、仕様にない |
| 4 | 判定できない手順は、自己確認 | ブラウザ・OS が先に処理するキー(Ctrl+W・Ctrl+T・Alt+Tab・Win キーなど。`reservedReason`)を含む手順は、判定せず、「答えを見る」→「できた / できなかった」で、自分で確認する。**この画面では押さないよう警告**する(押すとタブが閉じる)。練習の方法として、すべて自己確認を選ぶこともできる(スマートフォン向け) | 判定できないものを、判定できたように見せない |
| 5 | 押しても反応しないとき | 練習中の各手順に「押しても反応しない(自己確認にする)」ボタン。**一覧が実機と外れても、練習が止まらない** | 一覧は目安で、ブラウザ・バージョンで違う |
| 6 | キーを受け取る場所と、抜け方 | キーを受け取るのは、**答えの枠だけ**(`role="application"`。キー入力を捕まえる部品の、正しい使い方。閲覧モードのスクリーンリーダーでも、キーがページに渡る)。枠にフォーカスがあるときだけ判定する。**Tab・Shift+Tab は、判定も抑止もせず、移動に使う**(Tab でボタンへ移れる)。枠の外では、判定しない。受け付けているかは、文字と枠の線(破線・実線)で示す。Esc は答えとして判定する(中断は「やめる」ボタン) | キーボードトラップ(WCAG 2.1.2)を作らない。単独の Tab・Shift+Tab を答えにする手順は、自己確認になる(判定できない) |
| 7 | 判定の細部 | 押したキーは位置(`event.code`)で読む(0011)。修飾キー(Ctrl・Shift・Alt・Win)の有無まで一致を求める。修飾キーだけ・押しっぱなし(repeat)・IME の変換中・対応していないキーは、判定せず(間違いに数えない)、案内する。枠の中では、押したキーの既定の動作(F5 での再読み込み・Ctrl+S での保存など)を止める | 練習で、ページが動かないように |
| 8 | 設定 | 練習の方法(キーを押して判定 / 答えを見て自己確認)、「キーを最初から表示する」(覚える練習。押して判定する手順だけ。ヒントには数えない)。設定は、画面の中で覚える(やめても、次の練習に残る)。保存はしない | スマートフォンでの利用と、覚える練習 |
| 9 | 結果の数え方 | できた手順(押して合った + 自己確認の「できた」)、**間違いも答えを見ることもなく、できた手順**、間違いの回数、答えを見た手順、スキップ、自己確認でできなかった手順 | 「できた」だけでなく、思い出せたかを見せる |
| 10 | 更新の仕方 | 合っている・違うだけのときは、枠を作り直さず、文と進み具合だけを、その場で更新する。手順が進んだときだけ、作り直して、フォーカスを新しい手順へ(結果では見出しへ)。結果は、読み上げ用の領域でも通知する | フォーカス・読み上げを乱さない |
| 11 | 公開 | 「0.2.0」。詳細ページの説明・FAQ・更新履歴・画面(練習)・動作環境を更新 | 小機能単位でのテスト公開(仕様 Phase 10) |
| 12 | プライバシー | 変更なし。練習の結果は、保存も送信もしない | データが増えない |

## 運営者の実機での確認(Windows。ブラウザの種類は記録していない)

「先に処理されるキー」の一覧が、実機と合っているかを、運営者が確認した(キーみちの「キーを押して入力」で押した結果)。**確認した10種類は、すべて一覧と合っていた**。

| キー | 実機の結果 | 一覧 |
|---|---|---|
| Ctrl+T・Ctrl+W・Ctrl+Tab | ブラウザの機能が動く(ページに入らない) | 入っている |
| Ctrl+N | ブラウザが先に処理 | 入っている |
| Alt+F4・Alt+Tab・Win キー | Windows が先に処理 | 入っている |
| F5・Ctrl+S・数字 0〜9 | 入力できる | 入っていない |

未確認(一覧には入れている): Ctrl+Shift+N・Ctrl+Shift+T・Ctrl+Shift+W・Ctrl+F4・Ctrl+PageUp/PageDown・Ctrl+1〜9(Ctrl との組み合わせ)・Ctrl+Alt+Delete・Ctrl+Shift+Esc、macOS の一覧すべて。

## 未確認・既知事項

- **確認したのは Edge(Windows・headless)だけ**。headless では、Ctrl+W などがページに届いてしまうため、「先に処理されるキー」の実際の動きは、上の運営者の確認に頼っている。macOS・JIS 配列の実機・スマートフォンは未確認
- **スクリーンリーダーでの実際の読み上げは未確認**(`role="application"` で、閲覧モードでもキーが渡る想定だが、NVDA・VoiceOver で確かめていない)
- 練習中に、ブラウザ・OS が先に処理するキーを、うっかり押すと、タブが閉じるなどして、練習の途中の状態が失われる(結果は保存しない設計のため、被害は、その練習だけ)
- 単独の Tab・Shift+Tab は、判定できない(自己確認になる)
