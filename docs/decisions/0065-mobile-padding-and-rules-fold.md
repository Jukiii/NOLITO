# 0065: スマホの左右の余白・ダッシュボードの「遊び方」を畳む(Issue #163)

## 背景

運営者が、Issue #163 で、次の 2 点を依頼した(2026-10-02)。

- スマホ版で、文字が画面のはしから始まっていて、見にくい。
- タイピングゲームで、文字が多くて、見にくい。

## 原因

- 各ページの `<main class="main container">` で、`.main { padding: var(--space-8) 0; }` が、`.container { padding-inline: var(--space-4); }` よりあとに書かれていた。`padding` の一括指定が、左右の余白を 0 にしていた(同じ詳細度のため、あとの規則が勝つ)。幅 375px で、本文の左端が 0px だった(ヘッダー・フッターは `.container` だけなので、余白があった)。
- ゲームのダッシュボードは、「遊び方」の 8 項目が、スタートの前に、常に全部出ていた。スタートのボタンが、最初の画面の外に出ていた。

## 決定

- `.main` を `padding-block` だけにした(`layout.css`)。左右の余白は、`.container` の値(`--space-4`)になる。全ページに効く。
- ダッシュボードの「遊び方」を、開閉できる `<details class="game__rules">` にした。**最初は閉じる**。項目の中身・順序は変えていない。見た目は「くわしい設定」(`.game-setup__more`)と同じ(`game.css` で、規則を共有)。プレイ画面には、開閉の部品を置かない(0023 前後の決め)ので、ダッシュボードだけ。
- 「文字が多い」の解釈は、運営者の依頼文に詳しい指定がなかったため、私が決めた。プレイ画面(距離ゲージ・場面・単語・入力欄)は、すでに必要なものだけなので、変えていない。別の見せ方がよければ、Issue で依頼してもらう。

## 影響範囲

- `.main` の左右の余白が、0 から `--space-4` になった。全ページの本文が、左右に 16px ずつ内側に入る。横幅 100%(0063)は保たれる(はみ出しなし)。
- 記録・データ・API は、変更なし。プライバシーポリシーの版も、変更なし。

## テスト

- `tests/mobile-input.test.js` に、`.main` が `padding` の一括指定でないこと・「遊び方」が開閉でスタートの前にあることを追加。
- 既存の `tests/game-ready.test.js`(並び)・`tests/touch-operation.test.js`(`summary` の高さ)が、通ることを確認。
- 幅 360・375・402px で、全 30 ページに横のはみ出しがなく、本文の左端が 12px 以上あることを、ブラウザで確認。
