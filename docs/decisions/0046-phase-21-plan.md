# 0046 Phase 21 の計画(テーマ・文字サイズ・キーボード操作・アクセシビリティ強化)

日付: 2026-09-24 / 対象: Phase 21「ライト・ダーク・システムテーマ。ブラウザ設定＋サイト内文字サイズ。サイト全体キーボード操作。コントラスト、色以外の表現、視認性、アニメーション軽減。設定はLocalStorage／アカウント同期。」

「自立で」という運営者の指示により、実装前の確認を待たず、計画・実装方針を Claude Code の判断で決定した。

## 現状の確認

- 色は、すでに `tokens.css` の CSS カスタムプロパティ経由で指定されている(`components.css` の `.modal::backdrop` の1か所だけが例外。この PR で直す)。`tokens.css` 自身のコメントに「Phase 21 のダークテーマは、このファイルの色トークンを上書きして対応する」とあり、この Phase での対応を、あらかじめ想定している
- フォーカスの視認性(`:focus-visible`)・スキップリンク・`prefers-reduced-motion` への対応は、すでにある(`base.css`)。ゲーム画面は、`prefers-reduced-motion` に、すでに詳しく対応している(Phase 15〜17)
- サイト全体のキーボード操作は、個別には対応済み(スキップリンク・モーダル・ハンバーガーメニュー・ゲームの入力等)だが、横断的な確認はしていない
- 文字サイズは、ブラウザの既定に任せているだけで、サイト内で変える手段はない
- 設定を保存する既存のしくみ: ゲームの `settings.js`(`nolito:escape-boss:settings:v1`)、ツールの `store.js`(`nolito:tool:<id>:<workspace>:v1`)、同意の `consent-core.js`。**サイト全体の見た目の設定(テーマ・文字サイズ・アニメーション)は、どのページでも使うため、これらとは別の、新しいキーにする**
- アカウント同期は、Phase 19 PR2(`game_progress`)で、同じ考え方(D1 に要約を持つ・押すと保存/読み込み)の実装例がある。この Phase でも、同じパターンを再利用する

## この PR(1)の決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 選べる項目 | 「ライト」「ダーク」「システム(既定)」の3つ | 仕様どおり |
| 2 | 保存先 | `localStorage` の新しいキー `nolito:theme:v1`(値は `"light"` / `"dark"` / `"system"`)。既存の記録・設定のキーとは分ける | サイト全体の見た目の設定は、ゲーム・ツールの記録とは性質が違うため |
| 3 | 反映の方法 | `<html>` の `data-theme` 属性(`light`/`dark`/`system`)。CSS は、`:root`(ライトが既定)→ `@media (prefers-color-scheme: dark)` かつ `:not([data-theme="light"])` の場合にダークへ → `[data-theme="dark"]` で、システム設定に関係なく強制的にダークへ、の3段階。「ライト」を明示すると、OSがダークでも、ライトのまま | 明示した選択が、OSの設定より、常に優先される。「システム」は、OSの変更にも追従する |
| 4 | ちらつき防止(FOUC) | `<head>` の先頭に、小さいインラインスクリプト(ES Modules ではない。同期実行)を置き、`localStorage` を読んで `data-theme` を、CSS が読み込まれる前に設定する。読み取りに失敗しても(プライベートブラウズ等)、既定(システム)のまま、落ちない | JS の読み込み(`type="module"`は非同期)を待つと、最初は常にライトで表示され、ダーク選択時に一瞬ちらつく。全ページの `<head>`(手書き18ページ+生成の2テンプレート)に、同じ内容を置く |
| 5 | 切り替えの場所 | フッターに「テーマ」の `<select>`(ライト/ダーク/システム)。既存の「アクセス解析の設定」ボタンと同じ、サイト全体の設定として並べる | サイト全体の設定を置く場所が、すでにフッターに決まっている(既存の設計を踏襲) |
| 6 | ダークの配色 | `tokens.css` に、明度を反転させた新しい値を追加(暖色系の黒 `#181611` を基調に、質感を保つ)。**文字色・背景・強調色の組み合わせは、すべて WCAG AA(通常文字 4.5:1・UI部品 3:1)以上のコントラスト比になるよう、計算のうえ決めた**(`tests/theme.test.js` で、比率を検査する)。アクセント色(`--color-accent`。金色)は、ライト・ダーク共通(暗い背景でも、明るい背景でも、はっきり見えるため) | 色だけの見た目でなく、実際に読める配色にする |
| 7 | モーダルの背景幕 | `.modal::backdrop` の色(唯一のトークン化されていない色)を、新しいトークン `--color-backdrop`(暗い半透明。ライト・ダーク共通)に切り出す。ダークにしても変えない(背景を暗くする幕は、どちらのテーマでも同じ役目) | 「色はトークン経由」の既存ルールを、例外なく満たす |
| 8 | ゲームの場面の背景 SVG(既知の制限) | 職種ごとの場面の背景 SVG(Phase 15 PR2)は、ライトテーマ向けに、コントラスト比を計算して作った(`tests/backgrounds.test.js`)。ダークテーマでは、この背景(装飾・`aria-hidden`)が、薄く・見えにくくなることがあるが、**この PR の範囲では直さない**(追ってくる人・単語・入力欄など、操作に必要な要素には影響しない)。作り直しは、必要になった時点で、別Issueで検討する | 180枚以上のゲームの絵をすべてダーク対応させるのは、この PR の範囲を大きく超える。装飾要素(`aria-hidden`)なので、機能への影響はない |
| 9 | キャラクターの絵(SVG) | 同様に、ダークテーマ向けの作り直しはしない(既存の13色パレット・ポップな配色は、暗い背景でも、太い輪郭のおかげで、判読できると判断) | 同上。実際にブラウザで確認し、問題があれば、別Issueにする |

## テスト

- `tests/theme.test.js`(新規): ライト・ダーク、それぞれの配色の組み合わせが、WCAG AA のコントラスト比を満たすことを、計算で検査する。`data-theme` の3状態の切り替えロジック(純粋関数)
- `tests/site.test.js` 等の既存テスト: 色がトークン経由であること(`.modal::backdrop` の直書きをなくす)の確認を追加
- 全18ページの `<head>` に、FOUC防止のインラインスクリプトがあることを検査する新規テスト
- ブラウザ(headless Edge): ライト/ダーク/システムの切り替え、ちらつきがないこと(初回読み込み時のスクリーンショット比較)、OSの設定変更への追従(システム選択時)、複数の代表ページ(トップ・ゲームのダッシュボード・アカウント・検索)での見た目の確認

## テスト結果(この PR(1)完了時点)

- `npm run check`(lint・Prettier・単体テスト): **全 1844 件、成功**(`tests/theme.test.js` の 30 件を含む)。コントラスト比の検査(ライト・ダークの各配色ペア、WCAG AA)も、すべて通過
- ブラウザ(headless Edge・軽量な静的サーバーで確認)。計 17 件、すべて成功:
  - 初期表示(`system`・OSライト)は、ライトの配色。OSダークに切り替えると、自動でダークの配色に追従する(`data-theme` を明示していない場合)
  - フッターの `select` で「ダーク」を選ぶと、即座に配色が変わり、`localStorage`(`nolito:theme:v1`)に保存され、`<html data-theme="dark">` になる。再読み込みしても、FOUC防止のインラインスクリプトが、CSS 読み込み前に `data-theme` を反映する(ちらつきの確認:初回の `computedStyle` から、すでにダークになっている)
  - 「ライト」を明示すると、OSがダークでも、ライトの配色のまま(明示の優先を確認)
  - 「システム」に戻すと、`localStorage` に `"system"` が保存され、以後は OS の設定に追従する
  - トップ・ゲームのダッシュボード・検索・アカウント・スタイルガイドの5ページで、ダーク選択がページ遷移後も引き継がれる
  - モバイル幅(375px)でも、フッターのテーマ `select` が表示・操作でき、選択が反映される
  - テーマの `select` に対応する `<label>` があることを確認(スクリーンリーダー対応)
- スクリーンショットを目視確認: ライト・ダークとも、カード・ボタン・フォーム・バッジ・リンクの文字が、背景に対してはっきり読める。スタイルガイドの色見本の**ラベル文字列(`bg #fffaf0` 等)は、トークン名の定義値を示す静的な記載であり、実行時のテーマに関係なく固定**(見本の意図どおりで、修正不要と判断)
