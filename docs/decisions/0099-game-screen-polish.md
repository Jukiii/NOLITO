# 0099 ゲーム画面の配置・テーマ・追跡表現(Issue #243)

## 背景

運営者から、メインの入力画面を上下中央に置くこと、開始・セリフの表示が背景に隠れないこと、乗り物の向きと動きを直すこと、ネオン表現をやめてテーマに合わせることを依頼された。0067・0068・0074・0091 で採用した、全テーマ共通の暗いアーケード配色は、この依頼に合わせて置き換える。

## 決定

- ゲームの開始・プレイ・結果画面は、現在のテーマの意味トークン(色・角丸・線・影)を使う。暗い固定パレット、光る縁・文字、点滅する明るさの演出は使わない。ゲーム画面の影は、テーマによらず控えめな実線の影にする。
- プレイ画面の内容は、縦の余白の中で上下中央に置く。低い横向き画面では、既存の Phase 22 の規則どおり、入力欄が画面内に収まることを優先する。
- 全画面の追跡シーンは背景に保ち、吹き出し・開始/終了バナーは独立した前面レイヤーに置く。どちらも飾りとして読み上げず、文字の設定は既存の `textContent`、演出を飛ばす操作は既存のキー・クリックを保つ。
- セダン・リムジン・ヘリの絵を右向きに反転する。先輩と自転車は元の向きを保つ。反転は6コマの画像ではなく追跡枠に適用し、コマ送りの切り抜き位置を保つ。乗り物は、揺れを小さく・ゆっくりし、リムジンの明滅するつやをなくす。
- 先輩の走りは、上下の揺れと前傾が見える動きにする。OS・サイト設定の「動きを減らす」は引き続き尊重する。

## 影響範囲

- CSS・プレイ画面の表示レイヤーのみ。記録・進行・スコア・ランキング・保存形式・外部通信は変えない。
- 開始・セリフ・ゲームオーバーの演出は前面に表示される。背景の人物・道路は入力欄の後ろに残る。
- ゲームの開始画面・プレイ画面・用語確認・結果画面の製品スクリーンショットは、この環境に日本語フォントがなく、文字が豆腐表示になったため更新しない。読めない画像を公開せず、実機に近い日本語表示環境で撮り直す。

## テスト

- `tests/arcade-ui.test.js`: テーマトークン・上下中央配置・オーバーレイの前後関係・反転・乗り物の動き。
- `tests/staging.test.js`・`tests/lines.test.js`: 吹き出しとバナーがシーンから独立しても、読み上げ対象外・飛ばす操作・文字表示が保たれること。
- `npm run check` と `npm run audit` を実行する。
- Chromium で開始・プレイ・用語確認・結果の画面遷移を実行し、画面サイズと前面レイヤーを確認した。スクリーンショットはフォント不足のため採用しない。
