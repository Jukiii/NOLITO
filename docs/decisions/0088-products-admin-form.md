# 0088 プロダクトの管理画面を入力フォームにする

- 日付: 2026-10-03
- 関連: Issue #195・#162・決定 0051・0087

## 経緯

記事の管理画面(0087)は入力フォームだが、プロダクトの管理画面(Phase 26 PR 2b)は、1 件分の JSON をそのまま書く形のままだった。Jさんが管理画面で管理したいのは、書き方を覚えなくても使える形なので、プロダクトも入力フォームにする。

## 変えたこと

- `/account/admin/products/` の画面だけを、入力フォームに替えた。一覧(編集・削除)と、1 つのフォーム(新規作成・編集で共用)。編集ダイアログと JSON の textarea はなくなった。削除の確認ダイアログ(再認証の案内つき)は、そのまま。
- 項目: 基本(ID・カテゴリ・名前・説明・タグ・おすすめ)/ 公開の状態(状態・版・公開日・更新日・URL・詳細ページ・ボタンの文字)/ 画像 / 対応するもの・データの保存(チェックボックス)/ 料金(種類・金額・無料の範囲・将来の有料機能)/ 配布・購入 / 詳しい説明(空行で段落)/ 行を増やせる 4 つ(スクリーンショット・動作環境・よくある質問・更新履歴)。
- 値の変換は `admin/product-form.js`(DOM に触れない純粋な関数。`productToValues`・`valuesToProduct`)。入力欄は `admin/product-editor.js` が、項目の定義(`FIELD_GROUPS`・`ROW_LISTS`)から作る(`el()` だけ。`innerHTML` は使わない)。ページの制御は `admin/products-page.js`。
- ID は新規のときだけ入力できる(更新では変えられない。`product-id-mismatch`)。

## 変えないこと

- 保存の形(D1 `products` の JSON 1 件分)・管理 API・検証(`products/schema.js` の `validateProduct`。サーバーと共有)・監査ログ・削除の再認証(`recent: true`)。入力のしかたの間違い(金額が空など)は、変換で隠さず、サーバーと同じ検証が指摘する(`details` をそのまま表示)。
- フォームが扱わない項目は、いまのスキーマにない。スキーマに項目を足すときは、`productToValues`・`valuesToProduct`・`FIELD_GROUPS` を一緒に直す(テストが、入力値の全項目に入力欄があることを検査)。

## テスト

- `tests/admin-product-form.test.js`: 実際の 2 件のプロダクトが、入力値を経由して元に戻り、検証も通る・新規のひな形・料金・空欄の扱い・段落/行の分割・金額が空のときの指摘・入力欄の定義と入力値の一致。
- `tests/admin-products-page.test.js`: スクリプトが探す属性が HTML にある・`innerHTML` を使わない・管理ページの行き来。
- ヘッドレスの Edge で、管理者としてログインした状態の模擬サーバー(API は模擬)を使い、フォームが描かれること(24 の入力欄・4 つの行の一覧・プロダクト 2 件の一覧)・横にはみ出す要素がないことを確認した。本番での保存の操作は、Jさんが行う。
