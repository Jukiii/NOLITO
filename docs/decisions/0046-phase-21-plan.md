# 0046 Phase 21 の計画(テーマ・文字サイズ・キーボード操作・アクセシビリティ強化)

日付: 2026-09-24 / 対象: Phase 21「ライト・ダーク・システムテーマ。ブラウザ設定＋サイト内文字サイズ。サイト全体キーボード操作。コントラスト、色以外の表現、視認性、アニメーション軽減。設定はLocalStorage／アカウント同期。」

「自立で」という運営者の指示により、実装前の確認を待たず、計画・実装方針を Claude Code の判断で決定した。

## 現状の確認

- 色は、すでに `tokens.css` の CSS カスタムプロパティ経由で指定されている(`components.css` の `.modal::backdrop` の1か所だけが例外。この PR で直す)。`tokens.css` 自身のコメントに「Phase 21 のダークテーマは、このファイルの色トークンを上書きして対応する」とあり、この Phase での対応を、あらかじめ想定している
- フォーカスの視認性(`:focus-visible`)・スキップリンク・`prefers-reduced-motion` への対応は、すでにある(`base.css`)。ゲーム画面は、`prefers-reduced-motion` に、すでに詳しく対応している(Phase 15〜17)
- サイト全体のキーボード操作は、個別には対応済み(スキップリンク・モーダル・ハンバーガーメニュー・ゲームの入力等)だが、横断的な確認はしていない
- 文字サイズは、ブラウザの既定に任せているだけで、サイト内で変える手段はない
- 設定を保存する既存のしくみ: ゲームの `settings.js`(`nolito:escape-boss:settings:v1`)、ツールの `store.js`(`nolito:tool:<id>:<workspace>:v1`)、同意の `consent-core.js`。**サイト全体の見た目の設定(テーマ・文字サイズ・アニメーション)は、どのページでも使うため、これらとは別の、新しいキーにする**
- アカウント同期は、Phase 19 PR2(`game_progress`)で、同じ考え方(D1 に要約を持つ・押すと保存/読み込み)の実装例がある。この Phase でも、同じパターンを再利用する

## この PR(2)の決定

対象: サイト内文字サイズ・サイト全体のキーボード操作の点検・コントラスト/色以外の表現の点検・アニメーション軽減のサイト内切替。

### 現状の確認

- `base.css` に、すでに `@media (prefers-reduced-motion: reduce)` の全体ルールがあり、コメントで「サイト内の切替設定は Phase 21 で対応する」と、この PR を予告済み
- 動きを減らす判定の JS 側の読み取りは、ゲーム(`games/escape-boss/main.js` の `reducedMotion()`)の1か所だけ(`matchMedia("(prefers-reduced-motion: reduce)").matches`)。ここに、サイト設定の上書きを足す
- フォーカスの視認性(`:focus-visible`。太い枠線+オフセット、色だけに頼らない)は、すでに `base.css` に、サイト全体のルールとしてある
- 文字サイズは、`tokens.css` の `--font-size-*` が、すべて `rem` 単位(ルートのフォントサイズからの相対値)なので、**ルートの `font-size` を変えるだけで、サイト全体が連動して拡大できる**設計に、すでになっている

### 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 文字サイズの選択肢 | 「標準」「大きめ」「特大」の3つ(既定=標準) | 仕様の「サイト内文字サイズ」に対応。選択肢を増やしすぎない |
| 2 | 文字サイズの保存 | `localStorage` の新しいキー `nolito:font-size:v1`(`standard`/`large`/`xlarge`)。`components/font-size.js`(theme.js と同じ形の、DOM非依存の純粋関数+初期化) | テーマと同じ設計を踏襲。記録・ツールのキーとは別 |
| 3 | 文字サイズの反映方法 | `<html data-font-size="large\|xlarge">`(標準は属性なし)。`tokens.css` の `:root[data-font-size="large"] { font-size: 118.75%; }` ・ `:root[data-font-size="xlarge"] { font-size: 137.5%; }` で、ルートのフォントサイズを変える(`--font-size-*` は rem のまま変えない。サイト全体が連動して拡大される) | 個別のトークンを増やさず、ブラウザの拡大表示と同じ仕組み(ルートのフォントサイズ)に乗る。レイアウト崩れが起きにくい |
| 4 | アニメーション軽減の選択肢 | 「システムの設定に合わせる(既定)」「アニメーションを減らす」の2つ(**「常に動かす」は選べない**) | OSが「動きを減らす」を指定している利用者に対して、サイト側が動きを強制的に戻すのは、アクセシビリティ上、不適切(前庭障害等への配慮)。上乗せ(減らす方向)だけを許す |
| 5 | アニメーション軽減の保存 | `localStorage` の新しいキー `nolito:motion:v1`(`system`/`reduce`)。`components/motion.js`(同じ形) | 同上 |
| 6 | アニメーション軽減の反映方法 | `<html data-reduced-motion="reduce">`(既定=属性なし)。`base.css` の既存の `@media (prefers-reduced-motion: reduce)` ブロックに加え、`:root[data-reduced-motion="reduce"]` でも同じルール(`*` のアニメーション・トランジションを止める)を適用する。ゲームの `reducedMotion()` にも、`document.documentElement.dataset.reducedMotion === "reduce"` を、`matchMedia` の結果とORで足す | 既存の `prefers-reduced-motion` 対応(Phase 15〜17)の実装に、サイト設定を上乗せする形。二重管理を避けるため、CSSのルール自体は複製せず、セレクタを2通り用意する形にする |
| 7 | FOUC防止 | 既存のテーマのインラインスクリプト(全ページ)に、`nolito:font-size:v1`・`nolito:motion:v1` の読み取りも追加し、`data-font-size`・`data-reduced-motion` も、CSS読み込み前に反映する | テーマと同じ理由(ちらつき防止)。3つの設定を、同じ1つのスクリプトにまとめる(スクリプトを3つ並べない) |
| 8 | UIの場所 | フッターの「テーマ」の隣に、「文字サイズ」「アニメーション」の `<select>` を追加(同じ `site-footer__settings` の中) | サイト全体の設定を置く場所が、すでに決まっている(PR1を踏襲) |
| 9 | サイト全体キーボード操作の点検 | **新機能は追加せず、既存の実装を、実ブラウザでキーボードのみ操作して点検する**(Tab順・フォーカスの可視性・キーボードトラップの有無)。対象: ヘッダーのドロップダウン・モバイルメニュー・モーダル(インポート確認等)・検索の絞り込み・ゲームのプレイ画面と練習モード(既存のEsc/Tab仕様を再確認)。問題が見つかれば、この PR で修正する | 個別には対応済み(スキップリンク・モーダル・ハンバーガーメニュー・ゲームの入力等、既存の決定ログに記載)。仕様が求めるのは「横断的な点検」であり、この PR で実際に点検し、結果を記録する |
| 10 | コントラスト・色以外の表現の点検 | **新機能は追加せず、既存の実装を、コードレビュー形式で点検する**(バッジ・状態表示が、色だけでなく文字も伴っているか)。問題が見つかれば、この PR で修正する | 同上。すでに Phase 15(危険時の判断)・Phase 17(ルールの合図)・Phase 20(更新種別のバッジ)で「色だけに頼らない」設計を明記済みなので、その実装が保たれているかを確認する |

### 除外(この PR ではやらないこと)

- 文字サイズ・アニメーション軽減の**アカウント同期**は、PR3 で扱う(この PR では `localStorage` だけ)
- ゲーム内の個別設定(`settings.js` の音量等)との統合はしない(サイト全体の見た目設定と、ゲーム固有の設定は、別のキーのまま)

  - **結論: 個別には対応済みだった実装(スキップリンク・モーダルのEsc・ハンバーガーメニュー等)が、横断的に見ても、キーボードトラップなく機能している。この PR で見つかった問題はなし**(コードの修正は行っていない)

  - **結論: 既存の実装が、色だけに頼らない設計を保っていることを確認した。この PR で見つかった問題はなし**(コードの修正は行っていない)
