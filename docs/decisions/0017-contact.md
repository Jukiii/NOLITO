# 0017 Phase 10 PR 3: 問い合わせフォームの決定事項

日付: 2026-09-20 / 対象: Phase 10「問い合わせフォーム＋メール」「初期はユーザー報告・アクセス解析」。Phase 10 の 3 つの PR(バックアップ 0015 → 更新履歴 0016 → **問い合わせ**)の 3 つ目。Issue #13(お問い合わせ先を決める)に対応する。

## 背景

- about・プライバシーポリシー・サポートの 3 か所が、「お問い合わせ先は、準備中」だった。
- 仕様は「問い合わせフォーム＋メール」。**メールを送る(通知する)には、独自ドメインが要る**可能性が高く(Cloudflare のメール送信は、任意の宛先には有料プランが要り、送信元のドメインの設定も要る。未確認)、外部のメール送信サービスを使うと、問い合わせの内容が第三者に渡る。ドメインは、まだ決めていない(Issue #19)。
- そこで、**フォームで受け付けて D1 に保存し、運営者が手元で読む**形にした。メールの通知は、ドメインを決めてから足す。

## スコープ

- **含める**: `/support/` のフォーム、`GET/POST /api/contact`、`inquiries` テーブル(`migrations/0003_inquiries.sql`)、運営者用のコマンド(`npm run inquiries`)、**プライバシーポリシー v2**、about・サポートの文言、手順書(`docs/contact-setup.md`)
- **含めない**: メールの通知・自動返信メール(ドメインの後)、Cloudflare Turnstile(外部のスクリプト)、問い合わせの管理画面(Phase 26 以降)、ログインとの結びつき

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 場所 | `/support/` の「不具合・ご要望・お問い合わせ」の節(`#contact`)にフォームを置く。新しいページは作らない | 既存の窓口の場所を、そのまま、使えるようにする。about・ポリシーは、ここへリンクする |
| 2 | 項目 | 種類(不具合の報告・ご要望・質問・その他。必須)・対象のプロダクト(`products.json` から。任意)・内容(10〜2000 文字。必須)・返信用のメールアドレス(**任意**。ないと返信できないと明示)・環境の添付(チェック。**既定はオフ**) | 最小限の個人情報。不具合の調査に、環境が役立つが、選んだときだけ |
| 3 | 環境の添付 | 選んだときだけ、**画面の大きさ・言語・選んだプロダクトのバージョン**(ブラウザが送る)と、**User-Agent**(サーバーが、通信の情報から取る)を保存する。**送る前に、添付する内容を、画面に見せる**。形式は、決まった書式だけ(自由な文字列は受けない) | 何を送るかを、利用者が見て選べる |
| 4 | 保存 | D1 の `inquiries`(`id`・`created_at`・`category`・`product_id`・`message`・`email`・`env_info`・`status`(`new` / `done`)・`resolved_at`)。**`user_id` は持たない**(ログインしていても、結びつけない)。`status` は、サーバーが `new` にする(クライアントの値は、見ない) | 個人情報を増やさない |
| 5 | メールは送らない | 通知・自動返信は、しない。運営者が、`npm run inquiries` で、読みに行く(週に 1 回程度)。返信は、運営者のメールソフトから | ドメインが未定。問い合わせの内容を、第三者(メール送信サービス)に渡さない |
| 6 | ボット対策 | **罠の欄**(画面の外に置く。`aria-hidden`・`tabindex=-1`。`display:none` にしない)が埋まっている・**ページを開いてから 3 秒未満**の送信は、**保存せず、成功したように見せる**。1 つの送信元(IP の HMAC)から **1 時間に 3 件**、全体で **1 日 100 件**(罠・速すぎる送信も数える)。本文 16KB まで(宣言された大きさで、先に断る) | ボットに、失敗を教えない。洪水で D1 の無料枠を使い切らない |
| 7 | Turnstile は使わない | Cloudflare Turnstile(外部のスクリプトを、読み込む)は、いまは導入しない | 第三者のスクリプトを増やさない(同意・ポリシーの範囲を広げない)。スパムが増えたら、検討する |
| 8 | 入力の検査 | 画面(`contact/rules.js`)とサーバー(`_lib/contact.js`)で、**同じ規則**(上限・種類・制御文字)。サーバーが、最終の判断をする。**制御文字(改行・タブ以外)・見かけを変える双方向制御文字・不正なサロゲートは、断る**。テストで、画面とサーバーの判断が同じことを検査する | 画面だけの検査は、回避できる |
| 9 | 表示の安全 | 画面は `el()`(textContent)だけ。**サーバーは、内容を、応答・ログ・監査ログに、出さない**(`{ ok: true }` だけ。監査ログは種類だけ)。運営者の端末に表示するときも、**制御文字を `?` に置き換える**(外の人が書いた内容で、端末の画面を書き換えられないように) | 内容は、外の人が書いたもの |
| 10 | 保存期間 | 対応済み(`done`)にしてから **180 日(約 6 か月)**で、運営者が `--purge` で削除する。未対応のものは、消えない。バックアップも、直近 6 か月分まで(0015) | 「対応が終わってから、6 か月を目安」と、ポリシーに書く |
| 11 | 運営者用のコマンド | `npm run inquiries`(未対応の一覧)・`--all`・`--done <ID>`・`--purge`(件数だけ。消さない)・`--purge --yes`。ID は、決まった形だけ(SQL に入れるため)。ファイルに書き出さず、外へ送らない。本物の D1 には、`--remote`(0015 の一時設定) | 個人情報を、手元の端末に表示するだけ |
| 12 | 設定がないとき | `CONTACT_ENABLED=true` と、DB・`SESSION_SECRET`・`SITE_ORIGIN` がそろうまで、何もしない。`GET` は `{ enabled: false }`、`POST` は 503、ページは「準備中」。**Google の設定(アカウント機能)とは、独立** | プレビューが壊れない。アカウントの設定なしで、有効にできる |
| 13 | **プライバシーポリシー v2** | 版を **2** に上げる(同意の取り直し)。§6 に、お問い合わせフォーム・アカウント(限定公開)・バックアップの取り扱い、開示・訂正・削除の請求を追加。§7 に、利用するサービス(Cloudflare・Google)を追加。§8 に、改定の履歴。§1・§9 は、フォームへ | **個人情報の取得を、初めて、公開のページで始める**(第三者への提供・保存期間・利用するサービスの変更)。CLAUDE.md の基準(同意に関わる内容の変更)を満たす。副作用: アクセス解析の同意を、全員が、もう一度求められる |
| 14 | ポリシーとの整合 | 画面に書いた約束(保存期間・取得する情報)が、ポリシーと同じであることを、テストで検査する。`analytics.js` の版・ポリシーのページの版・同意の版が、そろっていることも検査する | 書いてあることと、実際が、ずれないように |
| 15 | 保存形式(D1) | `migrations/0003_inquiries.sql`。`docs/auth-setup.md` の「D1 に貼る SQL」に、コメントなしの同じ内容を載せた(`tests/migrations-doc.test.js` が一致を検査) | 本番の D1 に、Console で貼るため |

- `npm run check` 成功(867 件)。新規: API 32(設定・保存・環境の添付・ボット対策・回数制限・CSRF・大きさ・障害・ログに出さない)/ 画面・ポリシー(規則が、サーバーと同じ判断・メッセージ・クライアント・ページの静的な性質・ポリシー v2 との整合・ソースに見えない制御文字がないこと)/ 運営者用コマンド(SQL を、本物と同じ SQLite で実行・ID の検査・端末への表示の無害化・wrangler の出力の読み取り)

## 見つけて直した不具合

- ソースに、**見えない双方向制御文字**が、そのまま入っていた(書き込みの過程で、エスケープが展開された)。文字コードから、正規表現を組み立てる書き方に直し、**ソース全体に、制御文字・双方向制御文字がないこと**を、テストで検査する
- テストの誤り(実装の不具合ではない): 回数制限に、テスト自身が当たっていた・`undefined` が既定値になる・共通のファイルまで走査していた
