# データのバックアップと復元(運営者向け)

本番の D1(データベース)には、**利用者のメールアドレス・ライセンスなどの個人情報**が入っています。誤って消したり、壊れたりしたときに戻せるように、3つの層で守ります。

| 層 | 何を守る | どう守る | あなたの作業 |
| ---- | ---- | ---- | ---- |
| GitHub | コード・記事・商品のデータ | `git push` するだけ(すでに、そうなっています) | なし |
| D1 の Time Travel | 直近 **7日** の DB の状態 | Cloudflare が自動で(無料で・常に)取っています。([説明](https://developers.cloudflare.com/d1/reference/time-travel/)) | 戻すときだけ |
| 手元の書き出し | DB の全部(7日より前・DB ごと失ったとき) | **月に1回**、あなたのパソコンで `npm run backup:d1` | 月に1回 |

> **バックアップのファイルには、メールアドレスなどが入っています。** GitHub(公開)・チャット・共有フォルダには、**置かないでください**。コマンドは、リポジトリの中への保存を、断ります。

## 1. 準備(1回だけ)

1. **Node.js 22.13 以上**(確認の機能が使います。`node -v` で確認)。
2. Cloudflare にログインします(ブラウザが開きます)。

   ```
   npx wrangler login
   ```

3. 本番の D1 の **Database ID** を、Cloudflare のダッシュボード(**Storage & Databases** → **D1** → `nolito`)で調べて、環境変数に入れます(ID は、パスワードではありませんが、リポジトリには入れません)。

   - PowerShell(次回から、ずっと有効。**設定したあと、ターミナルを開き直す**):

     ```
     setx NOLITO_D1_DATABASE_ID "ここにDatabase ID"
     ```

   - その場だけなら、コマンドに `--id ここにDatabase ID` を付けます。

4. アカウントが複数ある場合は、`CLOUDFLARE_ACCOUNT_ID`(ダッシュボードの URL などに出ます)も、環境変数に入れます。

## 2. 月に1回の書き出し

```
npm run backup:d1
```

- ホームフォルダの `nolito-backups/` に、`nolito-d1-20260920T153000Z.sql` のような名前で保存されます(時刻は UTC)。
- 保存先を変えるときは `npm run backup:d1 -- --out D:/backups`(リポジトリの**外**だけ)。
- 書き出したあと、**メモリ上で復元を試して**、テーブルごとの件数を表示します(中身は、表示しません)。`問題は見つかりませんでした。` と出れば成功です。**問題があると、終了コード 1 で、理由を表示します。**
- 表示される件数が、ダッシュボードの Console の `SELECT COUNT(*) FROM users;` と大きく違わないか、ときどき見てください。

書き出したファイルは、あなたのパソコンの外(外付けディスク・自分専用のクラウドの、共有していないフォルダ)にも、1つ写しておくと、パソコンが壊れても安心です。

**古いものは削除してください。** 保管は、**直近 6か月分**までにします。理由: アカウントを削除した人の情報は、古いバックアップの中に、残っています。保管を6か月までにすれば、削除から最長6か月で、完全になくなります。

## 3. 書き出したファイルの確認(いつでも)

```
npm run backup:verify -- C:/Users/あなた/nolito-backups/nolito-d1-20260920T153000Z.sql
```

## 4. 復元する

### A. 最近(7日以内)の間違いを、戻す — Time Travel

たとえば、SQL を間違えて、データを消してしまったとき。**その時刻より前の状態に、DB 全体が戻ります**(その後の変更は、消えます)。

1. まず、今の状態を控える(戻しすぎたときの、やり直しに使う):

   ```
   npm run d1:remote -- time-travel info nolito
   ```

2. 戻したい時刻(UTC)を決めて、実行する(表示される確認に答える):

   ```
   npm run d1:remote -- time-travel restore nolito --timestamp=2026-09-20T12:00:00Z
   ```

3. サイトで、ログイン・一覧が動くか確認する。

### B. 7日より前・DB ごと失った — 書き出したファイルから

1. Cloudflare で、**新しい D1** を作る(名前は、何でもよい。例: `nolito-restore`)。その **Database ID** を控える。
2. 先に、ファイルが復元できるか確認する(ファイルは、戻したい日付のもの):

   ```
   npm run backup:verify -- <バックアップのファイル>
   ```

3. 新しい D1 に読み込む。**`--id` に、手順1で控えた「新しい D1」の ID を、必ず付ける**(`--id` は、環境変数の(本番の)ID より優先されます。付け忘れると、**本番に読み込んでしまう**ので、気をつけてください):

   ```
   npm run d1:remote -- execute nolito --remote --file <バックアップのファイル> --id ここに新しいID
   ```

4. Cloudflare の Pages → **Settings** → **Bindings** で、`DB` の向け先を、新しい D1 に変える(**Production**)。
5. **Deployments** から、再デプロイする。
6. `https://nolito.pages.dev/api/me` と、ログイン・ライセンスの一覧が動くか確認する。

バックアップには、セッション(ログインの状態)も入っているので、多くの人は、ログインしたままになります。**バックアップの時点より後に登録された人・ライセンスは、戻りません**(戻せる範囲は、そのバックアップの時刻まで)。

## 5. 復元の練習(最初に1回)

本番で初めて試すのは、こわいので、**最初のバックアップができたら、練習してください**。

1. `npm run backup:d1` で、1つ書き出す。
2. Cloudflare で、練習用の新しい D1 を作る(`nolito-test`)。
3. 上の「B」の手順2〜3を、**練習用の D1 の ID**(`--id`)で実行する(本番の ID では、実行しない)。
4. 練習用の D1 の Console で、`SELECT COUNT(*) FROM users;` が、本番と同じくらいか確認する。
5. 練習用の D1 を、削除する。

## 6. バックアップに入らないもの(別に、控えておく)

| もの | どこにある | 控え方 |
| ---- | ---- | ---- |
| Cloudflare の環境変数(`GOOGLE_CLIENT_SECRET`・`SESSION_SECRET` など) | Cloudflare | **パスワード管理ツール**などに、値を控える(チャット・GitHub には、置かない)。名前の一覧は `docs/auth-setup.md` |
| Google の OAuth クライアント(ID・シークレット・リダイレクト URI) | Google Cloud | クライアントのシークレットは、作り直せる。設定の手順は `docs/auth-setup.md` |
| ライセンスキーそのもの | あなたが控えたもの | DB にはハッシュしか入っていないので、**発行したときに控えたキー**を、失くすと、再発行になる |

## 7. 自動化していない理由

GitHub Actions で、定期的に書き出す方法もありますが、**公開のリポジトリに、本番の DB を読める秘密のトークンを置く**ことになり、書き出したファイルの置き場所も、公開されないものが要ります(GitHub の成果物は、公開のリポジトリでは、誰でも取得できると考えて、扱うべきです)。リスクに見合わないので、当面は、手元での書き出しにしています。
