# 0083: 語録の増量 バッチ 2 の下書き(Issue #182)

日付: 2026-10-03

## 背景

Issue #182 で、Jさんが バッチ 1 の公開(0081)のあと、「2. 進めて」(バッチ 2 を同じ流れで進める)と返信した。

## 決めたこと

- バッチ 2 は、拡張ファイル `content/vocabulary/<職種ID>.ext-batch2.md` に、**すべて `draft: true` / `review: pending` の下書き**として置く(計 296 語。エンジニア 48・営業 52・事務 56・飲食 51・講師・教育 53・接客販売 53 から、重複を除いた数)。**公開の JSON には入らない**(公開は 523 語のまま)。
- 人間の確認ルール(0026)は、0078 と同じ。Jさんが「OK」と言った語だけ、`draft` の行を消して公開する。**確認済み(`confirmed`)にするのも、公開するのも、Jさんの判断**(チャットで「公開して」と言われるまで公開しない)。
- 会社・地域・ツールで意味が違いうる語は、`note` で確認を求める(5 件)。
- 既存の語の id・内容は、変えていない。バッチ 2 の id は、各職種の最後の番号(バッチ 1 まで)の続きから振った。
- **同じ表記の語は、職種をまたいでも作れない**(検証のルール)。バッチ 1 までの公開済みの語・下書きと同じ表記の語は、除いた。説明が、既存の語とほぼ同じになる語(キッチン・食材費・学習指導案・宅配)も、事前に除いた。

## 影響

- 公開する語数・クリア率は、いまは変わらない(下書きは公開されない)。**公開するときに**、`tests/balance.test.js` のシミュレーションで、クリア率の階段(0006・0021)を確認し、語録の版・`products.json` の更新履歴も更新する。
- `tests/vocab-build.test.js` の、決め打ちの数(note・警告・拡張ファイルの数・エンジニアの語の数)を、実際の原稿に合わせた。
- `npm run vocab:check` の類似語の警告は 21 件(目安であり、重複とは限らない。確認シートで、Jさんに見てもらう)。
