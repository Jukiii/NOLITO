# 0016 Phase 10 PR 2: 更新履歴(/updates/)の決定事項

日付: 2026-09-20 / 対象: Phase 10「記事・プロダクト更新履歴」「小機能単位でテスト公開」。Phase 10 の 3 つの PR(バックアップ 0015 → **更新履歴** → 問い合わせ)の 2 つ目。

## 背景

- 各プロダクトの詳細ページには、更新履歴(`products.json` の `changelog`)がある。記事にも、更新日(`updated`)を書ける。ただし、**サイト全体で、何が更新されたかを見られる場所がない**。
- 仕様は「記事・プロダクト更新履歴」の 1 行。ここでは、**既存のデータを、1 つのページに集める**、最小の形にした。

## スコープ

- **含める**: `/updates/`(プロダクトの更新・記事の公開・記事の更新を、新しい順に、月ごとにまとめる)、フッターのリンク、スタイルガイドの見本、リリースの進め方の文書
- **含めない**: RSS・Atom、ホームへの「最近の更新」の表示、種類での絞り込み、お知らせ(更新以外の告知)、新しいデータの形

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | データ | **新しいデータの形を作らない。** `products.json` の `changelog`(バージョン・日付・変更点)と、`articles.json`(公開日・更新日)から、組み立てる | 二重に書かない。プロダクトの更新履歴を書けば、詳細ページと `/updates/` の両方に出る |
| 2 | 描き方 | ブラウザで、公開の JSON を読んで描く(`product-list.js` と同じやり方)。JavaScript がなければ、その旨を出す(`noscript`) | ビルドや生成物を増やさない。更新履歴は、検索のための、静的なページである必要が小さい |
| 3 | 種類 | プロダクトの更新 / 記事を公開 / 記事を更新。**種類は、色だけでなく、バッジの文字で示す** | アクセシビリティ(色だけに頼らない) |
| 4 | 並び順 | 日付の新しい順。同じ日は、同じプロダクトならバージョンの新しい方(数として比べる: 1.10.0 は 1.9.0 より新しい)、それ以外は、種類の順(プロダクト → 記事の公開 → 記事の更新)・題名の順。入力の並びに、影響されない | 毎回、同じ結果になる |
| 5 | まとめ方 | 月ごとに、見出し(h2「2026年9月」)でまとめる。項目は h3。h1 → h2 → h3 の順 | 長くなっても読みやすい。見出しで移動できる |
| 6 | リンク | プロダクトの更新は、詳細ページの `#changelog`(更新履歴の節)へ。詳細ページがなければ、遊ぶ・使うページへ。記事は、記事のページへ | その更新の、詳しい内容へ着く |
| 7 | 載せないもの | 準備中(`coming-soon`)のプロダクト。公開日と同じ日の記事の「更新」 | 未公開のものを、見せない。同じ日の更新は、重複になる |
| 8 | 安全側の挙動 | 不正なプロダクト(`usableProducts`)・不正な記事(日付・題名・説明・URL)は、**その項目だけ外して、ほかは表示し**、コンソールに警告を出す。記事の URL は、**このサイトの中のページ(`/` 始まり)だけ**(外部・`javascript:` は通さない)。表示は、`el()`(textContent 相当)だけ | 1 件の間違いで、ページ全体を壊さない。将来、管理画面から書かれても安全 |
| 9 | 公開の範囲 | 検索に載せてよい(`noindex` なし)。canonical・OGP を付ける。フッターに「更新履歴」を足す | 利用者が、変更を知るためのページ |
| 10 | 広告 | 他のページと同じ、非表示の枠(`data-ad-slot="page"`)だけ | 既存の方針(広告事業者のスクリプトは Phase 29 まで入れない) |
| 11 | 小機能単位でテスト公開 | コードは作らず、**進め方を文書にした**(`docs/release-process.md`): 1 機能 1 PR・`beta`(テスト版)の表示・更新履歴に書く・プレビューで確認・戻し方(Revert・Cloudflare のロールバック・D1 のバックアップ・緊急停止) | これまでの進め方が、すでに、その形 |

## テスト結果

- `npm run check` 成功。新規 28 件: 実際のデータ(1 件も欠けない・新しい順・リンク先が実在し `#changelog` の節がある・各商品の最新バージョンが先)、並び順(同じ日・バージョンの数としての比較・入力の並びに影響されない・入力を書き換えない)、項目の作り方(準備中を載せない・詳細ページなしのリンク・記事の更新)、記事のデータの検査(不正な日付・題名・URL(`javascript:`・`data:`・外部・`//`)を外す)、月ごとのまとめ、ページの静的な性質(noindex なし・フッターのリンク・noscript・`innerHTML` を使わない・外部へ通信しない・CSS はトークンだけ・スタイルガイドの見本)
- ブラウザ(headless Edge、`wrangler pages dev`)38 項目成功: 全件の表示・新しい順・見出しの階層・バッジの文字・詳細ページの `#changelog` に着く・記事に着く・フッターから着く・Tab の移動とフォーカスの枠・JavaScript なし・**壊れたデータ(不正な記事を外す・`javascript:` がリンクにならない・HTML を含む題名が実行されない・警告が出る)**・取得の失敗・375px の横スクロールなし・スタイルガイド・既存ページ 7 件

## 未確認・既知事項

- Microsoft Edge(Windows・headless)だけで確認。スクリーンリーダーでの実際の読み上げは、未確認(DOM・見出し・リンクの構造は確認)
- 更新の数が増えても、絞り込み・ページ送りはない(いまは 6 件)。増えたら、年ごとの折りたたみなどを、検討する
- RSS・ホームへの表示は、仕様にないので、作っていない
- 記事の「更新」は、記事の `updated` だけが元(記事の本文の履歴は、持たない)
