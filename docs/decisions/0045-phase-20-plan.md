# 0045 Phase 20 の計画(拡張可能なヘッダーメニュー・トップページ・検索)

日付: 2026-09-24 / 対象: Phase 20「拡張可能なヘッダーメニュー。おすすめ・カテゴリ別・最新情報のトップ。スマホはハンバーガー＋重要機能の下部固定。共通詳細＋カテゴリ追加＋カスタムページ。検索はプロダクト・記事・用語＋カテゴリ・タグ・職種絞り込み。」

「自立でPhase 20に進めて」という運営者の指示により、実装前の確認を待たず、計画・実装方針を Claude Code の判断で決定した。

## 現状の確認

- トップページ(`public/index.html`)は、まだ「ただいま準備中です」のプレースホルダーのまま(Phase 0 のまま、更新されていない)
- ヘッダーのナビ(`config/nav.js` の `mainNav`)は、フラットな一覧だけ(サブメニュー・展開の仕組みがない)。ファイル自身のコメントに「ナビ項目を増やすときはここだけを変更する(Phase 20 で拡張予定)」とあり、この Phase での拡張を、あらかじめ想定している
- モバイルは、ハンバーガーの開閉パネルだけで、「重要機能の下部固定」は、まだない
- カテゴリ(`categories.json`)・プロダクト(`products.json`)は、すでにデータ駆動(カテゴリを追加しても、コードを変えずに一覧が増える。`CLAUDE.md` の既存の記述どおり)。プロダクトの詳細ページ(`detail_path`)は、共通のテンプレートで生成済み(Phase 7)。カスタムページ(`/about/`・`/support/` など、カテゴリに属さない静的ページ)も、すでに自由に作れる(ビルド工程のない静的サイトのため)。**「共通詳細＋カテゴリ追加＋カスタムページ」は、既存のしくみで、すでにおおむね満たしている**と判断した
- 記事(`articles.json`)には、すでに `tags` がある。プロダクトには、まだタグがない(検索の絞り込みに使うため、この Phase で追加する)
- 検索の対象(プロダクト・記事・用語)を横断する一覧・検索の仕組みは、まだない

## PR の分割

| PR | 内容 |
| - | ---- |
| **1** | ヘッダーメニューの拡張(サブメニュー・展開に対応するデータ形と部品)。モバイルの「重要機能」下部固定バー |
| **2** | トップページ(おすすめ・カテゴリ別・最新情報)。プロダクトに `tags` を追加(検索の準備) |

## この PR(1)の決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | データ形 | `mainNav` の各項目に、任意の `children: [{ label, href }]` を持たせられるようにする。既存の `available`(準備中)と両立する | 「ここだけを変更する」という既存の設計方針を保ったまま、階層を持たせる |
| 2 | 中身 | 「ゲーム」→「上司から逃げろで遊ぶ」「成績・実績を見る」。「ツール」→「キーみち」。「ソフト」(`available: false`)・「記事」(1記事のみ、一覧ページで足りる)には、まだ付けない | いま実在するページの中で、実際に便利な分だけ、先取りで付ける。空の見せかけの階層は作らない |
| 3 | 見せ方(PC) | 子を持つ項目は、ボタン(`aria-expanded`・`aria-haspopup="true"`)にし、クリックで、ドロップダウンの一覧を開閉する。ほかの項目をクリック・Esc・外側のクリックで閉じる。子がない項目は、これまでどおりリンクのまま | キーボード・スクリーンリーダーの両方で、開閉の状態がわかるようにする |
| 4 | 見せ方(モバイルの開閉パネル) | 子を持つ項目も、パネルの中では、常に開いた状態で、親リンク+子リンクを、そのまま並べて出す(パネルの中に、もう1段の開閉を作らない) | 狭い画面で、開閉が二重になるのを避ける。パネル自体が「隠す/出す」の役目を、すでに持っている |
| 5 | モバイルの下部固定バー | 幅 48rem未満のときだけ、画面下端に固定。「ホーム・ゲーム・ツール・記事」の4項目(`available: false` の項目は出さない)。現在地は、上のナビと同じ判定(`aria-current="page"`)で示す。本文の下に隠れないよう、`main` に、バーの高さぶんの余白を付ける | ui-guidelines.md の「モバイルはハンバーガー＋重要機能」を、文字どおり実装する。個数を絞るのは、親指の届く範囲に収めるため |
| 6 | 見た目 | 新しいアイコン(SVG)は作らない(文字のラベルだけ)。既存のトークン(色・余白)だけを使う | 最小限の変更で、既存のデザイン言語(ポップ・カジュアル、装飾は控えめ)を保つ。アイコンは、必要になった時点で、別途検討する |
| 7 | 既存のテストへの影響 | `mainNav`/`footerLinks` の形は保つ(`children` は追加のプロパティ)。既存の「ナビの実在チェック」(`tests/site.test.js`)は、`children` の `href` にも広げる | 404 を作らない、という既存の保証を、階層にも適用する |
