# 0055: Phase 30(最終リリース準備の文書)

## 背景

Phase 30 の仕様(`docs/01_phases/phase-30.md`)は、文書の一式(全体仕様・Phase 0〜30・設計・データ・セキュリティ・運用・各 Phase の個別文書・変更履歴・バージョン・理由・影響範囲・受け入れテスト・モバイル確認・公開・ロールバック・テンプレート・Claude Code 指示・語録テンプレート・AI プロンプト)が、そろっていることを求める。新しい機能は、求めていない。

現状を点検した結果、テンプレート・Claude Code 指示・語録テンプレート・AI プロンプト・各 Phase の仕様・運用(`operations.md`・`backup.md`・`release-process.md`)・決定ログ(54 件)は、すでにそろっていた。**足りなかったのは、次の 3 つ**:

1. 技術文書(`architecture.md`・`data-model.md`・`security.md`)が、初期の数行のまま。実装(D1 の 12 テーブル・管理 API・LocalStorage のキー・実際のセキュリティ対策)と食い違っていた。
2. 「受け入れテスト」「モバイル確認」の文書がなかった(`release-checklist.md` は 9 行の見出しだけ)。
3. 文書全体の入り口がなく、変更履歴・版がどこにあるかが、分からなかった。

## 決定

- 上の 3 つを、**文書だけ**で埋めた(コード・データ・マイグレーション・環境変数の変更はない)。
  - `docs/03_technical/` の 3 文書を、実装に合わせて書き直した(2026-09-30 時点)。
  - `docs/05_checklists/release-checklist.md` を、公開の前・モバイルと環境・公開の後・ロールバックに広げ、`docs/05_checklists/acceptance-test.md`(人が確かめる受け入れテスト)を新設した。
  - `docs/README.md` を新設した(文書の一覧・変更履歴と版の場所)。
- **仕様書(`00_overview/`・`01_phases/`)は書き換えない**(仕様の変更は、承認が要るため)。実装との差は、下の表に記録する。

## 仕様と実装の差(仕様書は変えていない)

| 仕様(`overall-specification.md` §3 など) | 実装 | 理由 |
| ---------------------------------------- | ---- | ---- |
| `/advertising/` | `/ads-policy/`(収益化・広告の方針。0054) | 広告を載せる前の方針の文書として作った。名前が違うだけ |
| `/contact/` | `/support/` の中の `#contact`(0017) | サポートの案内と同じページに置いた |

| 購入履歴(Purchase) | まだない | 有料のソフト・販売サービス・特定商取引法の表記が先(Issue #12) |

## 影響範囲

- 利用者に見える変更は、ない。運営者・開発者向けの文書だけ。
- プライバシーポリシーの版・D1・環境変数の変更は、ない。

## テスト結果

- 文書の内容(テーブル名・環境変数・キー・ページ・スクリプト)は、実際のリポジトリ(`migrations/`・`functions/`・`public/`・`package.json`)と照らして書いた。
