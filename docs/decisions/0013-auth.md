# 0013 Phase 9 PR 1: アカウント(Google ログイン)の決定事項

日付: 2026-09-20 / 対象: Phase 9「最初はGoogleログイン、メールログインは将来。プロフィール・成績・購入履歴・ライセンスを管理。ライセンスキー＋アカウント認証」。

Phase 9 は 2 つの PR に分ける。**この PR(1)**: ログイン・セッション・プロフィール(ニックネーム)・ログアウト・アカウントの削除・監査ログ・招待制。**PR 2(`phase-09-licenses`)**: ライセンスキーの登録・一覧、購入履歴(読み取りのみ)。

## スコープ

- **含める**: Google ログイン、セッション、ニックネーム、ログアウト、アカウントの削除(再ログインの確認つき)、監査ログ、招待制の許可リスト、`/account/`、設定手順書(`docs/auth-setup.md`)
- **含めない**: ゲームの記録のアカウントへの保存・オンラインランキング・LocalStorage からの移行(**Phase 19**)、メールログイン(将来)、名前・写真の取得、複数のログイン手段の連携、管理画面
- **一般公開は、この PR に含めない**。招待制(`SIGNUP_MODE=invite`)で始め、公開は、Issue #19 の項目がそろってから、小さな別 PR で行う

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 基盤 | Cloudflare Pages Functions(`functions/`)+ D1(SQLite)。ルートは `/api/*`・`/auth/*` だけ。静的ページの配信は、これまでどおり(無制限・関数を通らない) | すでに Pages を使っている。無料枠(関数 10万/日、D1 読み取り 500万行/日・書き込み 10万行/日・5GB)で、限定公開には十分 |
| 2 | 外部サービスの確認(作業ルール7) | 費用: 無料枠内(2026年9月に確認)。規約: Google のログインは、OAuth クライアントの利用規約に従う。セキュリティ: 下記。**Google の公開審査(ブランド確認)と、`nolito.pages.dev` がそのドメインの確認を通れるかは、未確認**(Issue #19) | 公開の前に、確かめる |
| 3 | 保存する情報 | Google の `sub`(変わらない ID。識別に使う)・メールアドレス・サイトのニックネーム。**名前・写真は取得しない**(スコープは `openid email` だけ)。ほかに、セッション(トークンのハッシュ)・監査ログ(日時・種類・user_id)・回数の制限(IP の HMAC) | 必要最小限 |
| 4 | ログインの方式 | 認可コード + **PKCE(S256)** + `state` + `nonce` の、リダイレクト方式。**ブラウザに Google のスクリプトを読み込まない**。コードの交換は、サーバー間で行い、クライアントシークレットは、サーバーの環境変数にだけ置く | 第三者のスクリプトを増やさない。同意の仕組み(ポリシー v1)を変えない |
| 5 | ID トークンの検証 | 署名(**RS256 だけ**。`alg=none`・HS256 などは拒否)・`iss`・`aud`(文字列で一致)・`exp`(時計のずれ 60 秒)・`iat`・`nonce`・`sub`・`email`・`email_verified === true`。鍵(JWKS)は 1 時間覚え、知らない `kid` のときだけ、1 分に 1 回まで取り直す。取得に失敗したら、通さない | 標準的な検証。ローテーションに追従する |
| 6 | ログイン途中の状態 | `state`・`nonce`・PKCE の verifier・戻り先・期限を、**HMAC で署名した Cookie**(10 分)に入れる。DB には書かない | ログインの試行で、書き込みを増やさない |
| 7 | セッション | 256 ビットの乱数のトークン。**DB には SHA-256 のハッシュだけ**(DB が漏れても、なりすませない)。Cookie は `__Host-nolito_session`(`Secure`・`HttpOnly`・`SameSite=Lax`・`Path=/`・Domain なし)。**無操作 30 日・最大 90 日**で切れる(最終利用の更新は、1 時間に 1 回まで)。ログインのたびに新しいトークン(固定化攻撃の対策)。1 人あたり最大 10 セッション(古いものから消える) | 標準的な作り。書き込みを抑える |
| 8 | CSRF | 状態を変える要求(POST・DELETE)は、**Origin が `SITE_ORIGIN` と完全に一致**し、かつ、**独自ヘッダー `X-NOLITO-CSRF: 1`** がある場合だけ受ける。本文は JSON(`Content-Type` を検査)。CORS は許可しない(別のオリジンからは、事前確認で、ブラウザが止める)。GET では、状態を変えない | `SameSite=Lax` だけに頼らない(ポートが違うだけの別オリジンは、同じサイト扱いになる) |
| 9 | 戻り先 | `next` は、`/account/` の決まったパスだけ(それ以外は既定へ)。エラーは `?error=<種類>` で戻し、種類は決まった語だけを、決まった文に変えて表示する(URL の値は表示しない) | オープンリダイレクト・表示の注入を防ぐ |
| 10 | 招待制 | `SIGNUP_MODE`(既定 `invite`)。`invite` のときは、`ALLOWED_EMAILS` にあるメールアドレスだけがログインできる(アカウントも作らない)。**リクエストのたびに再確認する**ので、リストから外すと、ログイン済みでも、すぐ止まる(ログアウトだけは、できる)。Google 側は、公開ステータス「テスト」+ テストユーザーで、二重に絞る | 連絡先(#13)・ポリシー v2・規約(#19)がそろう前に、個人情報を集めない |
| 11 | ニックネーム | 前後の空白を削り、1〜12 字(コードポイント)、制御文字は不可。**切り詰めずに、断る**(400)。既定は「ななしさん」。HTML の文字は、そのまま保存し、表示は `textContent` | ゲームの `NICKNAME_MAX`・`DEFAULT_NICKNAME` と合わせる(統合は Phase 19)。出力側で守る |
| 12 | アカウントの削除 | 確認の語(`{"confirm":"delete"}`)と、**直近 10 分以内にログインしたセッション**が要る。古ければ `403 reauth-required`。画面は、`/auth/google/login?reauth=1`(`prompt=login`)へ案内する。削除すると、利用者とすべてのセッションが消え、監査ログは `user_id` が NULL になる(匿名になる)。メールアドレスは、どこにも残らない | 取り消せない操作は、その場で本人だとわかる人だけ |
| 13 | 監査ログ | ログイン・失敗・拒否・ログアウト・プロフィール変更・削除・回数制限。**メールアドレスなどの個人情報は入れない**。失敗の理由は、決まった語(`id-token-audience` など)。180 日で削除(ログイン時に、ときどき)。書き込みに失敗しても、本来の処理は止めない | 不正の調査と、個人情報の最小化 |
| 14 | 回数の制限 | D1 に窓ごとの回数を持つ。キーは、`CF-Connecting-IP` を `SESSION_SECRET` で HMAC したもの(**IP は保存しない**)。login・callback: 20 回 / 10 分 / IP、profile: 30 回 / 10 分 / 利用者、削除: 5 回 / 10 分 / 利用者 | ログインの総当たり・書き込みの増加を抑える |
| 15 | 設定がないとき・想定外の失敗 | 必要な設定(`DB`・クライアント ID/シークレット・`SESSION_SECRET`(32 字以上)・`SITE_ORIGIN`)と `AUTH_ENABLED=true` がそろうまで、何もしない。`/api/me` は `{enabled:false}`、ほかは 503、login・callback は `/account/?error=unavailable` へ。ページは「準備中」を出す。**プレビューが壊れない**。D1 の障害などの例外は、`/api` は JSON の 500(`server-error`)、`/auth` は `/account/?error=failed` に変え、内容はログにだけ出す(ミドルウェアは `functions/api/`・`functions/auth/` に置く。ルート直下に置くと、静的ページまで関数を通り、無料枠を使うため) | 設定の前にマージ・プレビューができる |
| 16 | 本番以外の Google の差し替え | `GOOGLE_AUTH_URL` などの上書きは、`SITE_ORIGIN` が `http://localhost` で始まるときだけ効く | 本番の設定ミスで、偽の Google に向けられない |
| 17 | `wrangler.toml` | ローカル専用。**`pages_build_output_dir` を書かない**(書くと、Cloudflare のダッシュボードの設定が、読み取り専用になり、ファイルが正になる)。`database_id` はダミー | 本番の設定は、ダッシュボードだけで管理する |
| 18 | 公開の範囲 | フッター・ナビには、リンクを出さない。`/account/` は `noindex`。一般公開のときに、リンクを足す | 限定公開の間は、見つけられない |
| 19 | プライバシーポリシー | 版は、**上げない**(v1 のまま)。限定公開の間の取り扱いは、`/account/` に書き、一般公開の前に、ポリシー v2(版を上げる)へ移す(Issue #19) | 招待した少数の方への限定的な提供。公開が、同意の取り直しの区切り |
| 20 | 保存形式(D1) | `migrations/0001_init.sql`(時刻は UNIX 秒)。以降の変更は、新しい番号のファイルを足す(既存のものを書き換えない) | 本番の DB に、順番に適用するため |

## テスト方法

- 単体・結合(`node --test`): `tests/helpers/d1.js`(`node:sqlite` の D1 互換。migrations をそのまま適用)と、`tests/helpers/fake-google.js`(生成した RSA 鍵で署名した ID トークン・PKCE を検査するトークン交換。`fetch` を差し替える)。**外部には通信しない**
- ブラウザ(headless Edge)+ **`wrangler pages dev`(本物の workerd・D1)** + 自作の偽の Google(リポジトリには入れない)で、ログインから削除までを通した

## 見つけて直した不具合

- `upsertUser`: 初めてのログインが同時に 2 回来ると、UNIQUE の違反で落ちうる作りだった(1 つの `INSERT ... ON CONFLICT` に)
- 例外(D1 の障害など)が、Cloudflare の生のエラー画面になっていた(`/api`・`/auth` のミドルウェアで、JSON・リダイレクトに)
- `parseCookies`: 前に空白のある、名前のない Cookie(`; =bad`)を、名前が空の値として拾っていた(行を trim してから解析するように)
- テストの誤り(実装の不具合ではない): メールアドレスの長さの境界の数え間違い

## 未確認・既知事項

- **本物の Google でのログインは、運営者が、本番で確認した**(2026-09-20。ログイン・ログアウト・ニックネームの変更。招待していないアカウントは、ログインできなかった。**どちらで止まったか(Google のテストユーザー・サイトの許可リスト)は、見分けていない**)。ログインの設定の手順書の不備(貼る SQL のコメント・Type の選択)は、PR 2 で直した
- **`nolito.pages.dev` で、Google の公開審査(ブランド確認)を通れるかは、未確認**。通れないときは、独自ドメインが要る(Issue #19。決めていない)
- 一般公開の前に必要な項目: 連絡先(#13)・プライバシーポリシー v2・利用規約・Google の公開審査(#19)
- 回数の制限・古い記録の削除は、ログイン時の確率的な掃除(約 50 回に 1 回)。アクセスが少ないと、期限を過ぎた行が、しばらく残る(個人を特定できる値ではない)
- セッションの Cookie は、`SameSite=Lax`。`nolito.pages.dev` の別のプロジェクト(同じ `pages.dev` の他人)とは、`__Host-` の Cookie は共有されない
- ブラウザは、Microsoft Edge(Windows・headless)だけで確認。実機・ほかのブラウザ・スクリーンリーダーは未確認
- 静的ページを配信する Cloudflare の本番・プレビューでの動作(関数のデプロイ・`wrangler.toml` が無視されること)は、PR のプレビューで確認する
