# 語録バリデーション

## 機械が確認する(`npm run vocab:check`・`npm run check`。エラーがあると、ビルドが失敗する)

- [ ] 必須メタ情報(`job_id`・`job_name`・`version`・`updated_at`・`items`)と、`jobs.json` との一致
- [ ] 一意なID(職種の id + 3 桁の連番。全職種で重複しない)
- [ ] 日本語・読み・ローマ字の存在(ローマ字は、省略すると、読みから作る)
- [ ] ローマ字候補の形式(英小文字と - だけ)と、**実際に最後まで入力できること**。先頭が、画面に表示する書き方であること
- [ ] 難易度範囲(1〜5。読みの長さの決めとのずれは、警告)
- [ ] 役職IDの妥当性
- [ ] 重複ID・重複語(日本語・読み)の検出
- [ ] 説明(`explanation`)が、「。」で終わる 80 字以内の 1 行。詳細説明(`detail`)があるときは、「。」で終わる 300 字以内の 1 行
- [ ] 関連用語が、同じ職種の、ほかの語を指していること(公開する語が、下書きを指さない)
- [ ] 制御文字・向きを変える文字・幅のない文字が、入っていないこと
- [ ] 生成物(`public/data/vocabulary/*.json`)が、原稿と一致していること
- [ ] 類似語(表記は違うが、説明の文章が近い組。文字2-gramのDice係数によるしきい値以上の候補。目安)

## AI がチェックする(`npm run vocab:check -- --for-ai` の出力を渡す。結果は、参考)

- [ ] 説明の誤りの可能性・表記の不整合・難易度の不自然さ
- [ ] 機械が見つけた類似語の候補が、本当に紛らわしい・重複しているか

## 人間が最終確認する(必須。`npm run vocab:review` の確認シート)

- [ ] 危険・不適切・誤情報の人間確認(説明が、一般に確立した意味と合っているか。会社・地域・法令で違うものは、`note` に書いてあるか)
- [ ] 表記・読み・難易度が、自然か
- [ ] 確認できた語は、`review: confirmed` にし、下書き(`draft: true`)の行を消したか

## 公開後の改善提案(任意。`npm run vocab:check -- --improve` の出力を渡す。結果は、参考)

- [ ] 関連用語・学習ポイント・詳細説明の追加案(すでに公開している、関連用語がまだない語が対象)
- [ ] AI の提案を、原稿に反映するかどうかは、人間が決める(反映したら、上の流れをもう一度)
