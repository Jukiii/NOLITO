# 0036 Phase 18 PR 1: 記録の版 4・経験値・レベル・職種別熟練度

日付: 2026-09-23 / 対象: Phase 18「職種・役職・難易度を個別選択。開始前に報酬・特殊ルール等を表示。ハイスコア・称号・実績・復習・成長記録・隠し要素。スコア・称号・経験値・レベル。職種別熟練度と改善記録」。

Phase 18 は 4 つの PR に分ける(運営者が決めたこと。計画への「推奨案で」)。**この PR(1)**: 記録の版 4・経験値・レベル・職種別熟練度。**PR 2**: 難易度の選択と、開始前の確認欄(報酬・ルール・自己ベスト)。**PR 3**: 隠し実績・実績の種類の追加。**PR 4**: 成績ページの改善記録・ハイスコア表。

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 記録の版 | **4**(`DATA_VERSION`。版 1〜3 も読める)。各結果に `difficulty`(この PR では「ふつう」だけ)。進行状況に、累計の経験値(`exp`)・職種ごとの合計(`jobs`。`plays`・`clears`・`words`・`hits`・`miss`)・難易度ごとのクリア数(`difficultyClears`。名前は `役職:難易度`)・自己ベスト(`bests`。名前は `職種:役職:難易度`)を追加 | CLAUDE.md の記録の決まり(版を上げ、古い版を読める移行を書く) |
| 2 | 移行(版 1〜3 → 4) | **これまでの記録から、新しい項目を作る**(消えない): 経験値 = 累計の正解語数 × 10 + 累計クリア数 × 100 + 解放済みの実績の数 × 50。職種ごとの合計・自己ベストは、**残っている結果(最大 200 件)から作る**(それより前のプレイの分は、正しく数えられない。既知の制約)。難易度ごとのクリア数は、役職ごとのクリア数を「ふつう」として数える。移行前の元データ(版 3)は `:backup-v3` に一度だけ退避(既存の `:backup-v1`・`:backup-v2` と同じ仕組み) | 0025・0013 と同じやり方 |
| 3 | 経験値の計算 | 1 プレイ = 正解語数 × 10 + クリア 100(クリアのときだけ)+ 新しく解放した実績 1 つにつき 50。**難易度の倍率**をかける(PR 2 で使う。この PR では 1)。`levels.js`(純粋な計算) | 「仕様のスコア・称号・経験値・レベル」 |
| 4 | レベルの曲線 | 1〜50。レベル `L` に必要な累計の経験値 = `60 × (L-1)^1.7`(10 の位に丸め)。なだらかに増える(レベル 2 = 60、10 = 1090、30 = 8300、50 = 20180) | 遊ぶほど、じわじわ上がる |
| 5 | 熟練度の段階 | 6 段階(見習い・初級・初級・中級・上級・達人・マスター)。**その職種で打ち終えた語数と、クリア数の、両方**を満たしたときに上がる(`mastery.js`)。境目: 30 語 / 100 語・1 クリア / 300 語・3 クリア / 700 語・8 クリア / 1500 語・15 クリア | 「職種別熟練度」。クリアなしで語数だけ稼ぐのを避ける |
| 6 | 画面(この PR) | **プレイヤー欄**にレベル・バー・「経験値 N / 必要量」の文。**結果の画面**に、獲得経験値と(上がったときだけ)レベルアップの文(保存の警告とは違う、前向きな見た目)。**職種の選択欄**に、熟練度の段階名(乗り物の名前と同じ `sub`)。**成績ページ**に「職種別の熟練度」の節(期間・役職の絞り込みの影響を受けない。復習リストと同じ考え) | 「開始前に…表示」は PR 2(この PR は、常設の表示だけ) |
| 7 | 自己ベスト・難易度ごとのクリア数 | この PR では、**記録するだけ**(まだ画面に出さない。難易度の選択がないため)。PR 2 で、開始前の確認欄に使う | 先に、データの置き場所を作る |
| 8 | 影響 | ゲームの規則・距離・バランス・スコアの式・語録・出題は、変わらない。経験値・レベル・熟練度は、**遊びやすさに影響しない**(表示だけ) | 見た目・記録の追加だけ |
