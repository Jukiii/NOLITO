# 0050 Phase 25 の計画(AI活用: 改善提案・類似語チェック・流れの文書化)

日付: 2026-09-26 / 対象: Phase 25「AI対象は生成・調整・説明・学習ポイント・チェック・重複・改善提案。管理画面アップロード。ただし有料APIが必要なら手動。人間確認必須。AIなしで運用可能。無料サービス・無料環境を基本。」

Phase 25 の仕様書(`docs/01_phases/phase-25.md`)も一行の要約のみで、その大半(生成・チェック・人間確認必須・有料APIに依存しない・AIなしで運用可能)は、**すでに Phase 11・14 で実装済み**(`vocab-check.mjs --for-ai`・`docs/06_ai/` のプロンプト・`review`/`draft` による人間確認のゲート)。新しく作るべき部分を、チャットで運営者に確認し、3 つの候補(改善提案・類似語チェック・流れの文書化)すべてを実装する承認を得た。

## 現状の確認(着手前の点検)

- **生成**: `docs/06_ai/vocabulary-generation-prompt.md`(AIに下書きを作らせるプロンプト)。実装済み
- **チェック**: `npm run vocab:check -- --for-ai`(下書き・未確認の語を、AIに確認させるプロンプト)。実装済み
- **重複(完全一致)**: `id`・`japanese`・`reading` の重複は、`validateVocabulary`(エラー)。**職種をまたぐ、まったく同じ日本語表記**は、`vocab-stats.mjs` の `findIssues` が警告。実装済み
- **人間確認・AIなしで運用可能・有料APIに依存しない**: `draft`/`review` による原稿だけの状態管理、`npm run build:vocabulary` はAIを一切呼ばない。実装済み(この性質を、緩めない)
- **管理画面アップロード**: Phase 26(管理画面・RBAC)は未着手。この Phase では対応しない(既存方針: 「管理画面・AI の API との連携は、作らない」)
- **足りないもの**: (1) すでに**公開・確認済み**の語(下書きではない)への、改善提案の仕組みがない。(2) 完全一致ではない、**意味が近い語**(表記は違うが、実質同じ・紛らわしい)を見つける仕組みがない。(3) 生成 → チェック → 人間確認 → 公開という流れが、`docs/06_ai/` に、まとまった形で書かれていない(個々のプロンプト文書に、断片的に書かれているだけ)

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 公開済みの語への改善提案 | `npm run vocab:check -- --improve`(新オプション)。**公開済み(下書きでない)かつ、関連用語(`related_terms`)が空の語**を対象に選び、`docs/06_ai/content-improve-prompt.md`(新規プロンプト)で、AIに、説明・関連用語・学習ポイント・詳細説明の追加/改善を提案させる。**確認済み(`review: confirmed`)かどうかは、問わない**(内容の正確性の確認=既存の`--for-ai`と、内容を豊かにする改善提案は、別の関心ごとのため) | 実データで、180語中 68語が、関連用語・学習ポイント・詳細説明のいずれも持たない(点検済み)。これが、最も分かりやすく価値のある改善余地。**AIの提案は、原稿を直接書き換えない**(既存のチェックの仕組みと同じ。人間が、原稿を手で直し、`vocab:check`→`vocab:review`→確認、の流れを、そのまま使う) |
| 2 | 類似語チェック | `scripts/lib/vocab-similarity.mjs`(新規。DOM・ファイルに触れない純粋関数)に、`similarPairs(items, { threshold })`(語の `explanation` の文字列を、文字2-gramのDice係数で比較し、しきい値以上の組を返す)を追加。**完全一致は、すでに `findIssues` が検出するため対象外**(表記だけ違う「近い」語を探す)。`vocab:check` の警告・`--for-ai` のプロンプトに、候補の組を追加する | 有料APIなしで、決まった計算だけで動く簡単な目安が必要。文字2-gramのDice係数は、日本語の文章でも、形態素解析なしで、そこそこの精度が出る、軽い方法。**しきい値以上でも、必ず重複とは限らない**(人間・AIが、最終確認する) |
| 3 | 流れの文書化 | `docs/06_ai/README.md`(新規)に、生成 → 機械チェック(形式・重複・類似語)→ AIチェック → 人間確認(`vocab:review`)→ 公開(`build:vocabulary`)→(公開後)改善提案、という一連の流れを、1つの図・表にまとめる。既存のプロンプト文書は、内容を変えず、この文書から参照する | 個々の文書・コマンドは揃っているが、全体の流れが、どこにもまとまっていなかった(点検で判明) |
| 4 | 管理画面アップロード | **この Phase では対応しない**(Phase 26 待ち) | 管理画面自体が、まだない。既存方針(「管理画面・AI の API との連携は、作らない」)を変えない |
| 5 | 有料APIとの連携 | **作らない**。すべて、プロンプトを人が(または、人がAIに)渡す、いまの方式のまま | 仕様書の「有料APIが必要なら手動」「AIなしで運用可能」「無料サービス・無料環境を基本」を、そのまま守る |

### 除外(この PR ではやらないこと)

- 管理画面アップロード(Phase 26)
- 有料AI APIとの自動連携
- 類似語チェックの、AIによる自動判定(候補を出すところまで。「本当に重複か」の判断は、人間・AIチェックの会話に委ねる)
