# 0027 Phase 14 PR 2: 難語の詳細説明・学習ポイント・関連用語の表示

日付: 2026-09-21 / 対象: Phase 14「語録に…関連用語・学習ポイント。**基本短文、難語は詳細説明**。…」。PR 1(0026: Markdown 管理元・検証・確認の状況)の続きで、Phase 14 の最後の PR。

## 仕様と、現状の突き合わせ

| 仕様 | 状態 |
| ---- | ---- |
| 基本短文 | 済み(`explanation`。80 字以内・「。」で終わる。検証済み) |
| **難語は詳細説明** | **この PR**。データに `detail` を足し、画面に出す |
| 関連用語・学習ポイント | データには、あった(`related_terms`・`learning_points`)。**画面には、出ていなかった。この PR で出す** |

## 運営者が決めたこと(計画への「推奨案で」)

- **`detail`(詳細説明)を新しく足して、学習ポイント・関連用語と一緒に出す**(既存の `learning_points` だけで済ませない)
- 内容の見本: **難易度 3 の語から、リスクの低い技術用語を職種ごとに 1 語ずつ(計 6 語)**。残りは、運営者の確認の後

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | データ | 語の項目に、任意の **`detail`**(詳細説明)を足す。**「。」で終わる 1 行、300 字まで**(検証は `vocab-validate.mjs`)。**書いた語だけ**、公開の JSON に、`explanation` の直後の項目として入る(ない語には、項目を作らない。**既存の 174 語の JSON は、変わらない**)。原稿・テンプレート・AI 用プロンプトを更新 | 基本は短文(80 字)。難語だけ、詳しく |
| 2 | 出す場所 | 共通の部品 `review-item.js` を拡張。**結果の画面の「今回ミスした語」・用語確認の結果(ミスした語・今回の用語)・成績ページの復習リスト**の 3 か所に、同時に効く。**プレイ中の画面には出さない**(開閉の部品を押すと、入力欄のフォーカスが外れて、入力が止まるため) | 入力の邪魔をしない |
| 3 | 表示 | 短い説明は、いつも見える。**関連する語**は、説明の下に「関連する語: A、B」。**「くわしく」**(開閉できる `<details>`・見出しは `<summary>`)を開くと、詳細説明と「学習のポイント」の一覧が出る。**詳細説明も学習ポイントもない語には、出さない**。開閉の見出しは、キーボード(Enter・Space)で操作でき、高さは `--tap-size`(44px 以上)。目印(▶ 閉じている・▼ 開いている)は装飾で、意味は「くわしく」の文字で伝える。色・余白は、トークン | アクセシビリティ・モバイル |
| 4 | 安全 | 語録の文字列は、すべて `el()`(textContent 相当)。文字列でないもの・空の文字列は、捨てる(語録が壊れていても、落ちない)。**`<img onerror>` などを、ブラウザで、差し替えて確認**(文字として表示され、実行されない) | 将来、管理画面・AI からも語が入る |
| 5 | 内容の見本(6 語。**AI の下書き**) | リファクタリング(engineer-010)・先入れ先出し(food-service-029)・書類整理(office-008)・在庫確認(retail-011)・新規開拓(sales-010)・学習計画(teaching-029)。いずれも難易度 3。詳細説明(89〜129 字)と、学習ポイント 3 つ。**各語に `note` を付けた**(「詳細説明と学習ポイントを、新しく足しました(AI の下書き)。一般的な意味に合っているか、確認してください」)。`review: pending` のまま公開 | 運営者が、確認シートで確認する |
| 6 | 確認シート | 列「詳細説明」「学習ポイント」を追加。「詳細説明のある語: n 語」を、全体の点検に出す | 運営者が、新しい内容を、確認できる |
| 7 | 版 | 語録の版を 0.4.0 に(6 職種)。ゲームを **0.11.0** に(FAQ「言葉の『くわしく』には、何が出ますか?」・更新履歴) | 内容と画面が変わった |
| 8 | 影響 | **記録・スコア・バランス・出題は、変わらない**。用語確認・プレイ中の画面の作りも、変えていない | データと表示の追加だけ |
