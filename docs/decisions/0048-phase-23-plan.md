# 0048 Phase 23 の計画(役職ごとのBGM・効果音・全演出スキップ・セリフ設定・音の環境設定点検)

日付: 2026-09-25 / 対象: Phase 23「BGMは職種・役職・状況で変化。役職別効果音。全演出スキップと自動スキップ。セリフ速度・表示時間設定。音量・品質・アニメーション軽減。」

「自立で」という運営者の指示(フェーズ移行も含む)により、実装前の確認を待たず、計画・実装方針を Claude Code の判断で決定した。

## 現状の確認

- 音は、Web Audio で合成する固定の1パターン(BGM: 4小節・低音+メロディー。効果音: start/correct/miss/near/clear/over の6種類)。役職・職種・状況による違いは、まだない。CLAUDE.md には「職種・役職ごとのBGM・役職別の効果音・演出のスキップ設定は、Phase 23」と、あらかじめ書いてある(Phase 16 PR3 時点での予告)
- `roles.json` は、すでに役職ごとに `scene.motion`(動き)・`scene.outro`(終わりの演出)・`lines`(セリフ)を持つ、データ駆動の設計。**同じ考え方で、音の個性も、役職ごとの数値(倍率)として持たせる**のが、既存の設計と一貫する
- 演出のスキップは、すでにある(`staging.js` の `timeline.skip()`。Enter・スペース・Esc・場面のクリックで、手動で飛ばせる)。**「全演出スキップ」は、これを自動化する、新しい設定**だと判断した
- セリフの間隔(`lines.js` の `gapMs`)・表示時間(`main.js` の `BUBBLE_MS`)は、**すでに関数の引数として渡せる設計**(依存注入)。値を固定で使っているだけなので、設定から渡すだけで対応できる
- 音量(`settings.js` の `volume`)・アニメーション軽減(Phase 21 の `motion.js`)は、すでにある。「品質」だけが、新しい要素

## PR の分割

| PR | 内容 |

| **1** | 役職ごとのBGM・効果音(職種・役職・状況による変化) |

## この PR(1)の決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 「役職」による変化 | `roles.json` の各役職に、新しい `sound: { tempo, pitch }`(倍率。既定に近い 1.0 前後)を追加。`tempo` は BGM の速さ、`pitch` は BGM・効果音の高さの倍率。**役職が進むほど、わずかに速く・高くなる**(先輩 1.0/1.0 → 会長 1.2/1.1 程度)。既存の「役職が進むほど難しくなる」(0006決定ログ)設計に、音でも寄り添う | `roles.json` に、動き・演出・セリフと同じ形で追加でき、既存の設計と一貫する。倍率は控えめにし(最大20%程度)、不快な速さ・高さにならないようにする |
| 2 | 「状況」による変化 | 「危ない」状態(`isDanger`)の間、BGM の速さに、追加の倍率(`DANGER_TEMPO_BOOST`)をかける。危なくなくなったら、元に戻す。効果音の高さは変えない(BGMの速さだけ) | 既存の「危ない」判定(`isDanger`。ゲージ・場面・合図で、すでに共通して使っている)を、音でも再利用する。新しい判定を増やさない |
| 3 | 「職種」による変化 | **この PR では対応しない**(既知の制限)。職種ごとに異なる旋律を作ることは、6職種分の作曲という、大きなコンテンツ制作になり、この案件のデータ駆動・パラメータ調整という設計方針(役職の速さ・音の高さのような、数値の調整)を超える。職種の個性は、すでに背景の絵(Phase 15)で出している | 仕様書にない機能を、勝手に大きく増やさない(`.claude/CLAUDE.md` の方針)。音楽の作曲は、確認・調整が難しく、AIの下書き→人間の確認、という語録・セリフと同じ流れを踏める性質のものでもない |
| 4 | 役職別効果音 | 効果音(`SOUND_EFFECTS`)の周波数(`hz`・`to`)に、役職の `pitch` 倍率をかけて鳴らす(`effectNotes(name, pitch)`)。**音の種類・長さ・音色(wave)は変えない**(役職ごとに全く別の音を作ると、6役職×6種類=36通りの調整・確認が必要になり、過大)。高さだけを、役職に応じてずらす | 役職ごとの個性を、少ない変更で、聞き分けられる形で出す。既存の6種類の効果音の設計(Phase16 PR3)を壊さない |
| 5 | 実装の場所 | `sound.js`(純粋な計算)に、倍率を受け取る形に変更。`audio.js`(鳴らす係)に、`setRoleSound({ tempo, pitch })`(ゲーム開始のたびに1回。危ない状況の倍率もリセットする)・`setDanger(bool)`(状況による、一時的な倍率)を追加。`configure({ mode, volume })` とは別のメソッドにする(音量・モードの設定変更と、役職の音の個性は、変わる頻度・きっかけが違うため)。`main.js` は、`beginGame` で `sound.setRoleSound(roleSoundOf(role))`、危ない状態の変化ごとに `sound.setDanger(danger)`、`quit` で `sound.setRoleSound()`(既定に戻す)を呼ぶ | 既存の層分け(データ計算・鳴らす係・画面のつなぎ)を保つ。`configure` は既存のテスト・呼び出し側が多いため、シグネチャを変えず、新しい関心ごとは、新しいメソッドに分ける |
| 6 | 検証・データの形 | 新しいファイル `role-sound.js`(DOM・音に触れない純粋関数)に、`DEFAULT_ROLE_SOUND`・`roleSoundOf(role)`(役職から安全な倍率を取り出す。ない・壊れていれば既定)を置く。`roles.json` の全役職に `sound` を追加し、テストで検証する | `scene.js`・`outro-styles.test.js` と同じ、データの検証を独立させる設計を踏襲する |

### 除外(この PR ではやらないこと)

- 職種による音の変化(上記3)
- 全演出スキップ・セリフの速さ/表示時間の設定は PR2 で扱う
- 音の品質設定は PR3 で扱う

### テスト結果(この PR(1)完了時点)

- `npm run check`(lint・Prettier・単体テスト): **全 1938 件、成功**(`tests/role-sound.test.js` の新規22件を含む)
- **実装した内容**: `roles.json` の全役職に `sound: { tempo, pitch }`(先輩 1.0/1.0 → 会長 1.2/1.1、単調増加。最大でも1.3倍以内)。`role-sound.js`(新規)に `roleSoundOf`(壊れた値は、`tempo`・`pitch` それぞれ独立に既定へ)・`DANGER_TEMPO_BOOST`。`sound.js` の `bgmStepNotes`・`effectNotes` に、`pitch` 引数(既定1。後方互換)を追加。`audio.js` に `setRoleSound`・`setDanger`(BGMの拍の間隔を `BGM_STEP_SEC / (tempo × danger倍率)` で計算)。`main.js` の `beginGame`・`tick`・`quit` を配線
- ブラウザ(headless Edge。偽の `AudioContext` を注入し、実際に鳴らす指示=周波数・時刻を記録)のE2E、計3件、すべて成功: 先輩(既定)で音が鳴ること、社長(pitch=1.08)が先輩より平均して高い周波数で鳴ること、社長(tempo=1.15)が先輩よりBGMの拍の間隔が短い(速い)こと、を、実際のゲーム操作(職種・役職選択→開始→演出スキップ)を通して確認した
- 会長(裏ボス)は、解放条件があり、既定では選べないため、E2Eの比較には、解放条件のない社長を使った
- スクリーンショットの確認は、対象外(音のみの変更で、見た目は変わらない)。音色・音量そのものは、自動テストでは聞けないため、人による確認が別途必要(既存の方針。0032決定ログ)

## この PR(2)の決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 「全演出スキップ」の実装方法 | 新しい設定 `skipStaging`(既定オフ)。オンのとき、`beginIntro()`・`beginOutro()` で `timeline.start()` の直後に `timeline.skip()` を呼ぶ(**既存の「飛ばす」操作=Enter・スペース・Esc・場面のクリックと、まったく同じしくみ**を、開始の直後に自動で使うだけ) | 新しい進行のしくみを作らない。`timeline.skip()` は、すでに「残りを飛ばして、すぐ`onDone`を1回だけ呼ぶ」ことがテスト済み(`tests/staging.test.js`)なので、「結果は演出の前に保存、`onDone`で結果画面を1回だけ表示」という Phase16 PR2 の不変条件が、そのまま保たれる |
| 2 | セリフの速さ・表示時間の設定 | 新しい設定 `lineLevel`(`few`/`normal`/`many`。既定 `normal`)。`lines.js` に `LINE_LEVELS`(段階ごとの `gapMs`・`bubbleMs`)を追加し、`lineLevelOf(level)` で安全に取り出す。`createLines({ gapMs })`(既存の依存注入をそのまま使う)・`view.showBubble(..., bubbleMs)` に渡す | `lines.js`・`main.js` の該当箇所は、すでに `gapMs`・表示時間を引数として受け取れる設計(依存注入)だったため、値を設定から渡すだけで対応できた。新しい保存項目・新しい判定ロジックを増やさない |
| 3 | 段階の値 | 少なめ: 間隔 ×1.5(6000ms)・表示 ×0.75(1500ms)。ふつう: 変更なし(4000ms/2000ms)。多め: 間隔 ×0.625(2500ms)・表示 ×1.25(2500ms) | 「ふつう」は、これまでの値をそのまま保つ(既存プレイヤーの体験を変えない)。「少なめ」は、静かに集中したい人向けに、間隔を広く・短く。「多め」は、にぎやかにしたい人向けに、間隔を狭く・長く。倍率は、極端にならない範囲で選んだ |
| 4 | 用語確認での扱い | 両方の設定欄を、用語確認では隠す(`view.js` の `applyMode()`。既存の `data-graphics-option` 等と同じ枠組み) | 用語確認には、場面・演出・セリフが、そもそもない(Phase 12 の決定)。設定を出しても、意味がない |
| 5 | 画面の位置 | 「グラフィックを抑える」の直後、「苦手な語の出やすさ」の直前に、2つの設定欄を追加 | 既存の設定欄(explanation → graphics → weak → inputStyle → sound)の並びに、自然に割り込める位置。関連する見た目・演出の設定を、近くにまとめた |

### テスト結果(この PR(2)完了時点)

- `npm run check`(lint・Prettier・単体テスト): **全 1957 件、成功**(新規 `tests/staging-settings.test.js` 15件、`tests/lines.test.js` に `LINE_LEVELS`/`lineLevelOf` の新規5件を含む。既存の `tests/check.test.js`・`tests/sound.test.js`・`tests/lines.test.js` は、`DEFAULT_SETTINGS` の形が変わった分の期待値を更新)
- ブラウザ(headless Edge)のE2E、計8件、すべて成功:
  - 連続タイピングでは、2つの設定欄が見える。用語確認では、両方とも隠れる
  - 選択・チェックが、既存の設定キー(`nolito:escape-boss:settings:v1`)に保存され、再読み込みでも復元される
  - `skipStaging: true` のとき、開始の演出のバナー(`[data-banner]`)が、すぐ(200ms未満)に隠れる。`skipStaging: false`(既定)では、150ms後もまだ演出中で、約800ms(動きを減らす設定下)後に隠れる
  - 演出を自動で飛ばしたあと、「やめる」でダッシュボードに戻れる(スキップで進行が壊れていない)
- 「結果は演出の前に保存し、`onDone`のときだけ結果画面を表示する」という不変条件は、`timeline.skip()` を呼ぶ経路が、通常の飛ばす操作(Enter等)とまったく同じであるため、既存のテスト(`tests/staging.test.js`)が、そのままカバーしている
- スクリーンショットで、設定欄の見た目(連続タイピング・用語確認の両方)を確認した
