# 0038 Phase 18 PR 3: 隠し実績・実績の種類の追加

日付: 2026-09-24 / 対象: Phase 18「…隠し要素」の部分。

Phase 18 は 4 つの PR([[0036-phase-18-levels|0036]] のとおり)。PR 1: 経験値・レベル・熟練度。PR 2: 難易度の選択と、開始前の確認欄([[0037-phase-18-difficulty|0037]])。**この PR(3)**: 隠し実績・実績の種類の追加。PR 4: 成績ページの改善記録・ハイスコア表。

## 仕様と、現状の突き合わせ

| 仕様 | 状態 |
| ---- | ---- |
| 隠し要素 | いまの実績一覧は、すべて常時公開(未解放でも、名前・説明・条件が見える)。**この PR で「隠し実績」を追加** |
| 実績の種類の追加 | 12種類の実績(役職クリア・全役職クリア・ノーミス・僅差・速さ・全職種・累計クリア・累計語数)。**この PR で 4 種類を追加**(難易度クリア・全役職の難易度クリア・連続正解・職種の熟練度) |

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 隠し実績の仕組み | `achievements.json` の各項目に、任意の `hidden: true` を追加できるようにした。未解放の間、実績一覧(`view.js` の `achievementItem`)は、名前・説明・称号を隠し(「??? (隠し実績)」「まだ見つかっていません。条件を満たすと、内容が明らかになります。」)、解放すると通常どおり表示する | 条件を見せてしまうと、発見する楽しみが減る(「隠し要素」の趣旨) |
| 2 | 解放の瞬間は、必ず見える | 結果画面の「新しい実績」欄(`newAchievements`)は、`hidden` の有無に関係なく、常に名前・説明・称号を表示する(解放直後は `unlocked=true` として描画するため) | 解放した達成感を、隠したままにしない |
| 3 | 実績の総数・解放数は、隠さない | ダッシュボードの「解放済み N / 合計M」の集計は、隠し実績も数に含める | 「隠し実績がある」こと自体は、多くのゲームで一般的な演出(数だけ見える・内容は見えない) |
| 4 | 新しい実績の種類(4つ。いずれも、既存の `result`・`progress` の項目だけで判定し、保存形式は変えない) | ①`difficulty_clear`(指定の難易度でクリア。`result.difficulty`)②`all_roles_clear_difficulty`(先輩〜社長を、すべて指定の難易度でクリア。`progress.difficultyClears` + `storage.js` の `clearKey`)③`best_streak`(1プレイの連続正解が、しきい値以上。`result.streak`)④`job_mastery`(いずれかの職種が、指定の熟練度の段階に到達。`progress.jobs` + `mastery.js` の `masteryOf`) | Phase 18 PR 1・PR 2 で増えた記録の項目(難易度・連続正解・職種別熟練度)を、実績にも活かす |
| 5 | 追加した実績(すべて `hidden: true`) | 「修羅場をくぐり抜けた」(むずかしいで、いずれかの役職をクリア。称号「修羅場の生還者」)・「むずかしいの制覇者」(先輩〜社長を、すべてむずかしいでクリア。称号「むずかしいの覇者」)・「よどみない指運び」(1プレイで10語以上、連続正解)・「極めし者」(いずれかの職種で、熟練度マスターに到達。称号「極めし者」) | Phase 18 PR 2 で作った難易度・PR 1 の熟練度と、テーマ上つながりのある目標にした |
| 6 | `achievements.js` の依存 | `storage.js` の `clearKey`(純粋な文字列整形)・`mastery.js` の `masteryOf`(純粋な計算)を import した。どちらも DOM・保存・時計に触れない、既存の純粋関数の再利用 | `achievements.js` の「DOM・保存・時計に触れない」性質を保ったまま、既存の記録項目を判定に使うため |
| 7 | 影響 | 記録の版(5)・保存形式は変えない。新しい実績は、既存のプレイヤーにも、条件を満たしていれば、次のプレイで解放される(過去のプレイは遡って判定しない。既存の実績と同じ扱い) | データ形式に触れない、表示と判定ロジックだけの変更 |
