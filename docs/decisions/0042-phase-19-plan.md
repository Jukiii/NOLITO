## PR の分割

Phase 18 と同じく、複数の PR に分ける。後半(PR3・4)は、記録を初めて社外(運営者のサーバー)に送る、privacy-sensitive な変更のため、慎重に進める。

| PR | 内容 | プライバシーへの影響 |
| - | ---- | ---- |
| **1(この PR)** | ゲームの記録の JSON 書き出し・読み込み(バックアップ・機種変更用)。キーみちの `store.js` と同じ考え方 | なし(端末内のデータを、端末内で移すだけ) |
| 2 | アカウント移行: ログイン時に、端末の記録を、アカウントに結びつけて、運営者のサーバー(D1)に保存する(選択制。強制しない)。初回アクセス時の登録案内(控えめなバナー) | **あり**。ゲームの記録が、初めて運営者のサーバーに送られる(ポリシー改定・版を上げる必要) |
| 3 | プロフィールの公開範囲の設定(例: ランキングに、ニックネームを出す/出さない)。オンラインランキング(アカウントに結びついた記録を、参加した利用者の間で共有する) | **あり**。ほかの利用者にも見える、新しい種類の公開(ポリシー改定・版を上げる必要) |

PR2・PR3 は、**招待制(Issue #19)のまま実装してよい**(オンラインランキングは、アカウントを持つ人だけの間の機能。一般公開の判断とは、分けて進められる)。ただし、PR2・PR3 に着手する前に、プライバシーポリシーの改定内容を、運営者に確認する。

## この PR(1)の決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | 書き出し・読み込みの形式 | `public/assets/js/tools/store.js` の `exportJson`/`parseImport`/`importJson` と、**同じ考え方**(`format`・`version`・`data`を持つJSON。壊れている/新しすぎるものは断る。取り込み前のデータは`:before-import`に退避)。ゲームの`storage.js`は、`normalizeData`がすでに版1〜5の移行をこなせるので、**移行のしくみを重複させず、`normalizeData`を、取り込みの検証にそのまま使う** | 既存のしくみの再利用。安全側の挙動(壊れたデータを上書きしない)を、キーみちと揃える |
| 2 | 読み込みの動作 | **置き換え**(いまのデータを、書き出したデータに、まるごと置き換える)。マージ(両方の記録を混ぜる)は、しない | 「別の端末の記録を、この端末に持ってくる」という用途に合わせる。マージは、重複の判断が難しく、複雑になりすぎる |
| 3 | 画面の場所 | ダッシュボード(`/games/escape-boss/`)に、「記録の書き出し・読み込み」の節を追加(プロフィールの近く)。ファイルの選択・書き出しボタン・取り込み前の確認ダイアログ(取り消せないことを伝える) | ダッシュボードは、プロフィール・ランキング・実績など、記録全体を扱う画面のため |
| 4 | ファイル名 | `escape-boss-<日付>.json`(キーみちの`kii-michi-<日付>.json`と同じ命名) | 一貫性 |
| 5 | 影響 | 記録の形式・版(5)は変えない。既存のプレイ・保存・移行のロジックには、触れない | 表示と、新しい書き出し/読み込み関数の追加だけ |
