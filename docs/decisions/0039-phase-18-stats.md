# 0039 Phase 18 PR 4: 成績ページの改善記録・ハイスコア表

日付: 2026-09-24 / 対象: Phase 18「…ハイスコア…改善記録」の部分。

Phase 18 は 4 つの PR([[0036-phase-18-levels|0036]] のとおり)。PR 1: 経験値・レベル・熟練度。PR 2: 難易度の選択([[0037-phase-18-difficulty|0037]])。PR 3: 隠し実績([[0038-phase-18-achievements|0038]])。**この PR(4、最後)**: 成績ページの改善記録・ハイスコア表。

## 仕様と、現状の突き合わせ

| 仕様 | 状態 |
| ---- | ---- |
| ハイスコア | 成績ページに「ベストスコア」表は既にあったが、**役職ごと**(期間・役職の絞り込みの対象。直近 200 件の範囲だけ)。**この PR で、`progress.bests`(職種 × 役職 × 難易度の自己ベスト。[[0036-phase-18-levels|0036]] で記録だけ先に用意していたもの)を使った、絞り込みの影響を受けない表に置き換えた** |
| 改善記録 | 「成長グラフ」(推移)・「直近との比較」はあったが、**自己ベストを更新した瞬間の記録は、なかった**。**この PR で追加** |

## 決定

| # | 項目 | 決定 | 理由 |
| - | ---- | ---- | ---- |
| 1 | ハイスコア表の元データ | 旧: 表示中の範囲(`scope`。期間・役職の絞り込みの対象)の `results` から計算。**新: `progress.bests`**(記録の版 4 から、クリアのたびに更新される自己ベスト。範囲・件数の制限がない)。`stats.js` の `bestScoreTable(bests, { jobIds, roleIds, difficultyIds, bestKey })`(純粋関数。`bestKey` は `storage.js` のものを呼び出し側が渡す) | 「期間を短く絞ると、過去のハイスコアが表から消える」という、旧表の弱点をなくす。職種別の熟練度・復習リストと同じく、**期間・役職の絞り込みの影響を受けない**表にした |
| 2 | ハイスコア表の行 | **役職 × 難易度**ごとに 1 行(職種をまたいだ最高)。役職の並び × 難易度の並びの順(最大 15 行 = 5 役職 × 3 難易度)。難易度の列を追加した | 職種 × 役職 × 難易度をすべて展開すると、行が多すぎる(最大 90 行)。役職と難易度は、遊びの選択として意味が大きいが、職種はスコアへの影響が小さいため、代表の 1 職種にまとめた |
| 3 | 改善記録(新規) | `stats.js` の `bestScoreHistory(results, bestKey, { limit = 10 })`(純粋関数)。保存されている `results`(直近 200 件)を古い順にたどり、**職種 × 役職 × 難易度の組ごとに、自己ベストが更新された瞬間**(クリアした記録だけ)を、新しい順に最大 10 件返す。初回の記録は「はじめての記録」、更新は「自己ベストを更新(前回 N 点 → +M点)」と表示する | 「どれだけ伸びたか」を、グラフの推移だけでなく、**具体的な達成の記録**として見せる |
| 4 | 表示の位置 | ハイスコア表・改善記録は、どちらも「職種別の熟練度」の直後、**絞り込み(期間・役職)の前**に置いた(`data-scoped` の外) | 絞り込みの影響を受けないことを、位置でも示す(職種別の熟練度・復習リストと同じ並び) |
| 5 | 旧「ベストスコア」表・`bestScoresByRole` | **削除**(新しいハイスコア表に置き換え。同じ画面に、役職だけの表と役職×難易度の表の、2つを並べる必要はない) | 表示の重複を避ける |
| 6 | 影響 | 記録の形式・版(5)は変えない。既存の `progress.bests`(PR 2 から記録)を読むだけ。`engine.js`・スコア・ランキングは変えない | 表示と集計だけの変更 |
